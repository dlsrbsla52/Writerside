# 람다 표현식(축약)

람다 표현식과 메소드 참조는 자바에서 함수형 인터페이스(단 하나의 추상 메서드만 가진 인터페이스)를 간결하게 구현할 수 있도록 도와줍니다.  
예를 들어,

```java
myArray.iterator().forEachRemaining(System.out::println);
```

이 코드는 Iterator에 남은 요소들을 하나씩 꺼내 `System.out.println`으로 출력하는 동작을 합니다.  
여기서 `System.out::println` 메소드 참조가 내부적으로 어떻게 동작하는지 단계별로 살펴보면 다음과 같습니다.

---

### 1. **메소드 참조의 문법과 의미**

- **메소드 참조란?**  
    `System.out::println`은 메소드 참조(Method Reference)라는 문법입니다.  
    이는 기본적으로 람다 표현식의 축약형으로,
    
    ```java
    x -> System.out.println(x)
    ```
    
    와 동일한 역할을 합니다.
    
- **어떤 함수형 인터페이스에 맞춰지는가?**  
    `forEachRemaining` 메소드는 다음과 같이 정의된 Consumer 인터페이스를 매개변수로 받습니다.
    
    ```java
    @FunctionalInterface
    public interface Consumer<T> {
        void accept(T t);
    }
    ```
    
    여기서 타입 T는 컬렉션의 요소 타입으로 추론됩니다.  
    따라서, `System.out::println`은 `accept` 메서드를 구현하는 형태로 사용됩니다.
    

---

### 2. **컴파일 시 처리 과정**

- **타입 추론 및 호환성 검사**  
    컴파일러는 `System.out::println`이 Consumer의 `void accept(T t)` 메서드 시그니처와 일치하는지 확인합니다.  
    즉, 전달받은 인자 T를 받아 `System.out.println(T)` 호출이 가능한지 검증합니다.
    
- **람다 표현식으로의 변환**  
    컴파일러는 메소드 참조를 내부적으로
    
    ```java
    (T t) -> System.out.println(t)
    ```
    
    와 같이 해석합니다.
    
- **invokedynamic와 Lambda 메타팩토리**  
    자바 8부터는 람다 표현식이 컴파일될 때, 별도의 익명 내부 클래스가 생성되는 대신 `invokedynamic` 명령어를 사용하여 런타임에 해당 함수형 인터페이스의 인스턴스를 생성합니다.  
    이 과정에서 Lambda 메타팩토리(LambdaMetafactory)가 호출되어,  
    _상태가 없는(stateless)_ 람다의 경우 단일 인스턴스를 재사용할 수 있는 최적화도 이루어집니다.
    
- **예시: 내부적으로 생성되는 메소드**  
    컴파일러는 내부적으로 다음과 같은 **synthetic method** (합성 메소드)를 생성할 수도 있습니다.
    
    ```java
    private static void lambda$0(Object x) {
        System.out.println(x);
    }
    ```
    
    그리고 Lambda 메타팩토리를 통해 이 메소드를 호출하는 Consumer 인스턴스를 만들어 냅니다.
    

---

### 3. **런타임 동작 과정**

1. **메소드 참조 객체 생성**
    
    - `System.out::println`에 해당하는 Consumer 객체가 런타임에 생성됩니다.
    - 이 객체는 내부적으로 앞서 언급한 synthetic 메소드를 호출하는 방식으로 동작합니다.
2. **forEachRemaining 호출**
    
    - `myArray.iterator().forEachRemaining(consumer)` 호출 시, Iterator 내부에서 `hasNext()`와 `next()`를 반복하면서 각 요소에 대해
        
        ```java
        consumer.accept(element);
        ```
        
        를 호출합니다.
3. **Consumer.accept 호출 시 동작**
    
    - 위에서 생성된 Consumer 객체의 `accept` 메서드가 호출되고, 내부에서는
        
        ```java
        System.out.println(element);
        ```
        
        가 실행되어 해당 요소가 출력됩니다.

---

### 4. **전체 흐름 요약**

4. **작성 단계:**  
    개발자는
    
    ```java
    myArray.iterator().forEachRemaining(System.out::println);
    ```
    
    라고 작성합니다.
    
5. **컴파일 단계:**
    
    - 컴파일러는 `System.out::println`을 `x -> System.out.println(x)` 람다 표현식으로 해석합니다.
    - 해당 람다 표현식이 Consumer 인터페이스의 `accept` 메서드에 부합함을 확인합니다.
    - `invokedynamic`과 LambdaMetafactory를 통해 Consumer 인스턴스가 생성될 수 있도록 컴파일합니다.
6. **런타임 단계:**
    
    - Iterator의 `forEachRemaining` 메소드가 Consumer.accept를 각 요소에 대해 호출합니다.
    - Consumer.accept는 내부적으로 `System.out.println`을 호출하여 각 요소를 출력합니다.

---

### 결론

- **메소드 참조(`System.out::println`)는 람다 표현식의 축약형이며,**  
    컴파일러는 이를 `x -> System.out.println(x)`와 같이 해석합니다.
    
- **컴파일 시,**  
    LambdaMetafactory를 통해 해당 람다 표현식(메소드 참조)을 구현하는 Consumer 인스턴스가 동적으로 생성됩니다.
    
- **런타임 시,**  
    Iterator의 `forEachRemaining` 메소드가 각 요소에 대해 Consumer.accept를 호출하고,  
    이로 인해 `System.out.println`이 실행되어 요소들이 출력됩니다.
    

이와 같이, 자바는 람다 표현식과 메소드 참조를 통해 코드의 간결성과 가독성을 높이면서도, 내부적으로는 효율적으로 함수형 인터페이스의 인스턴스를 생성하여 동작하게 됩니다.
