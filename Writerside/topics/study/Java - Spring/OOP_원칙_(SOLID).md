# OOP 원칙 (SOLID)

### Single Responsibility Principle **SRP** (단일 책임 원칙)
- 하나의 클래스에는 하나의 역할과 책임을 주어야 한다. 
- 클래스는 단 하나의 기능 또는 목적을 가져야 하며, 그 클래스가 변경되어야 하는 이유는 오직 하나여야 한다.
- 결과적으로 코드가 더 명확하고, 수정이 쉽고, 버그 발생 가능성을 줄일 수 있다.

### Open/Closed Principle **OCP** - 개방 폐쇄의 원칙
- 소프트웨어 엔티티(클래스, 모듈, 함수 등)는 확장에는 열려 있어야 하지만, 수정에는 닫혀 있어야 한다.
- 새로운 기능을 추가할 때 기존 코드를 수정하지 않고도 확장할 수 있어야 한다.
- 이를 통해 기존 코드를 안정적으로 유지하면서도 기능을 확장할 수 있다.

### Liskov Substitution Principle **LSP** - 리스코프 치환의 원칙
- 서브타입은 언제나 자신의 기반 타입(base type)으로 교체할 수 있어야 한다.
	- 하위 클래스의 인스턴스는 상위 클래스의 인스턴스 역할을 하는데에 문제가 없어야 한다. 인터페이스가 클래스 관계, 상위 클래스와 하위클래스 관계를 얼마나 논리적으로 설계했느냐이다. 하위클래스가 상위클래스의 역할을 대신할 대에 논리적으로 맞아 떨어져야 한다.
- 객체는 프로그램의 정확성을 깨지 않으면서 부모 클래스의 객체로 대체할 수 있어야 한다.
- 리스코프 치환 원칙은 부모 객체를 호출하는 동작에서 자식 객체가 부모 객체를 완전히 대체 할 수 있다는 원칙이었습니다!

### Interface Segregation Principle **ISP** - 인터페이스 분리의 원칙
- 상황에 맞는 메서드만 제공하라는 원칙. 어떤 구현 클래스는 자신이 구현하지 않은 인터페이스를 사용하지 않아야 한다.
- 클라이언트는 자신이 사용하지 않는 메서드에 의존하지 않도록 인터페이스를 분리해야 한다.
- 하나의 큰 인터페이스를 여러 개의 작은 인터페이스로 나누어, 클라이언트가 필요한 기능만 선택적으로 구현할 수 있게 해야 한다.

### Dependency Inversion Principle **DIP** - 의존 역전의 원칙
- 고수준 모듈은 저수준 모듈에 의존해서는 안 되며, 둘 다 추상화에 의존해야 한다
	- 추상 클래스 또는 상위 클래스는 구체적인 구현클래스 또는 하위클래스에게 의존적이면 안된다는 뜻이다.
- 추상화는 세부 사항에 의존하지 않으며, 세부 사항이 추상화에 의존해야 합니다.
- 이를 통해 모듈 간의 결합도를 낮추고, 시스템의 유연성을 높일 수 있습니다.
