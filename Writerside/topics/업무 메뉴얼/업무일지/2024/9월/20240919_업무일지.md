### 중복 로직 통합 및 각 Exception별 에러 메세지 통합
#### 원인

노후화 된 모델 사용으로 인한(System.Web.mvc) 리퀘스트 파라미터 모델 바인딩 및 IIS 구동으로 인한 CI/CD 구축의 어려움이 있어 리펙터링 결정.

#### 문제 분석 및 전략

1. GETMethod, POSTMethod의 공통적인 비지니스 모델을 각 메소드마다 처리하고 있음
2. 클라이언트가 잘못된 데이터를 보낼 경우 해당 기능을 Exception 처리하여 클라이언트에 알려주고 있지 않음.
3. 필요하지 않은 로직을 통해 처리속도가 느려지고 있음
4. iis 사용을 통한 배포 및 파이프라인 구축의 어려움

#### 해결방안
1. 현재 사용중인 라이브러리(System.Web.mvc) -> Microsoft.AspNetCore.Mvc 변경 처리
2. GETMethod, POSTMethod의 로직 처리를 공통 비지니스 로직으로 통합하여 유지보수 
3. Server / Client Exception을 분리하여 Client의 감지 가능하게 변경

### 분기별 question_sync 등 동기화 테이블 데이터 이전 배치 개발
#### 원인
zocboDB to TmsDB는 현재 데이터 동기화가 일어나고 있으며, 이는 question_sync 테이블로 관리되어 새벽에 배치를 통해 처리되고 있음.
question_sync로 데이터 적재시 question_sync 테이블은 temp테이블로써 인덱스가 걸려 있지 않고, old 데이터들의 관리가 되지 않았음.
기존엔 개발자가 1년에 한번 데이터를 이관시켜주는 작업을 진행하고 있었으나, 2024년 데이터 이관처리 작업을 하지 않아 동기화시 데이터 로딩이 느려지는 현상 발생.

#### 해결방안
question_sync 테이블의 old데이터를 다른 question_sync_202409 등의 해당하는 월에 **데이터 이관 배치 개발**
이를 통해 old 데이터의 관리 및 temp 테이블의 컴팩트화를 통한 빠른 데이터 동기화 처리 가능
