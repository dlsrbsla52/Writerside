#### H회사의 전체 제품 단가 보다 큰 제품 출력을 하고자 한다. 괄호안에 들어갈 알맞는 용어를 작성하시오.



```sql
SELECT 제조사, 제품명, 단가  
FROM 제품  
WHERE 단가 > ( ) (SELECT 단가 FROM 제품 WHERE 제조사='H')
```



- 정답 및 해설
	주어진 SQL 쿼리에서 빈 칸에 들어갈 용어를 작성하고 해설해보겠습니다.
	
	### 문제 풀이
	문제에서는 H 회사의 전체 제품 단가보다 큰 제품을 출력하려고 합니다. 이 경우에는 **서브쿼리**를 사용하여 특정 조건을 만족하는 제품을 선택해야 합니다.
	
	```sql
	SELECT 제조사, 제품명, 단가  
	FROM 제품  
	WHERE 단가 > ( ) (SELECT 단가 FROM 제품 WHERE 제조사='H')
	```
	
	여기서 괄호 안에 들어가야 할 올바른 용어는 **`ALL`** 또는 **`ANY`**입니다. 두 가지 중 어떤 것을 사용하느냐에 따라 의미가 달라집니다:
	
	1. **ALL 사용**: 
	   - `단가 > ALL (SELECT 단가 FROM 제품 WHERE 제조사='H')`
	   - 이 경우, **H 회사의 모든 제품 단가보다 큰** 값을 찾습니다. 즉, H 회사의 모든 제품보다 단가가 더 높은 제품을 선택하게 됩니다.
	
	2. **ANY 사용**:
	   - `단가 > ANY (SELECT 단가 FROM 제품 WHERE 제조사='H')`
	   - 이 경우, **H 회사의 어떤 제품 단가보다라도 큰** 값을 찾습니다. 즉, H 회사 제품 중 하나라도 단가가 작은 제품보다 더 비싼 제품을 선택하게 됩니다.
	
	이 문제에서 **전체 제품 단가보다 큰 제품**을 찾으려면 **ALL**이 적절한 선택입니다. 왜냐하면 "전체 제품보다 큰"이라는 표현은 모든 제품의 단가보다 커야 한다는 의미를 포함하기 때문입니다.
	
	### 정답
	- 빈 칸: **ALL**
	
	### 최종 쿼리
	```sql
	SELECT 제조사, 제품명, 단가  
	FROM 제품  
	WHERE 단가 > ALL (SELECT 단가 FROM 제품 WHERE 제조사='H');
	```
	
	### 해설
	- **ALL 사용**: 
	  - `ALL`은 서브쿼리에서 반환된 모든 값을 비교합니다. 따라서 `단가 > ALL (...)`은 서브쿼리에서 반환된 모든 단가보다 큰 값을 가진 제품을 찾습니다.
	  - 주어진 테이블에서 `제조사 = 'H'`인 모든 제품의 단가를 찾고, 그 값들보다 더 큰 단가를 가진 제품들을 결과로 반환합니다.
	
	- **서브쿼리의 역할**:
	  - 서브쿼리 `(SELECT 단가 FROM 제품 WHERE 제조사='H')`는 H 회사 제품의 단가들을 반환합니다. 그 후 메인 쿼리는 이 값들과 비교하여 모든 값보다 큰 단가를 가진 제품들을 필터링합니다.
	
	따라서 `ALL`을 사용하면 H 회사의 모든 제품 단가보다 더 비싼 제품만이 결과에 포함됩니다.

```sql
SELECT count(col2)

```

- 정답 및 해설
	주어진 문제의 SQL 쿼리를 분석하고 그 결과를 구해보겠습니다. 테이블의 데이터를 바탕으로 쿼리의 조건에 맞는 결과를 계산합니다.
	
	### 주어진 테이블

	| Index | col1  | col2  |
	|-------|-------|-------|
	| 1     | 2     | Null  |
	| 2     | 3     | 6     |
	| 3     | 5     | 5     |
	| 4     | 6     | 3     |
	| 5     | Null  | 3     |
	
	### 주어진 SQL 쿼리 {id="sql_1"}
	```sql
	SELECT count(col2)  
	FROM TABLE  
	WHERE col1 in (2, 3) OR col2 in (3, 5);
	```
	
	이 쿼리는 두 가지 조건에 해당하는 `col2`의 값을 기준으로 `count`를 수행합니다.
	
	#### 조건 분석
	- **`col1 IN (2, 3)`**: `col1` 값이 `2` 또는 `3`인 행을 선택합니다.
	- **`col2 IN (3, 5)`**: `col2` 값이 `3` 또는 `5`인 행을 선택합니다.
	- 조건은 **OR**로 연결되어 있기 때문에 두 조건 중 하나라도 만족하면 해당 행을 선택합니다.
  	
	### 조건에 해당하는 행 찾기
	각 조건을 만족하는 행들을 찾아봅시다:
	
	1. **`col1 IN (2, 3)`**:
	   - `Index = 1`: `col1` 값이 `2` (조건 만족)
	   - `Index = 2`: `col1` 값이 `3` (조건 만족)
	
	2. **`col2 IN (3, 5)`**:
	   - `Index = 3`: `col2` 값이 `5` (조건 만족)
	   - `Index = 4`: `col2` 값이 `3` (조건 만족)
	   - `Index = 5`: `col2` 값이 `3` (조건 만족)
  	
	### 조건에 해당하는 모든 행
	두 조건 중 하나라도 만족하는 행을 모두 고려하면:
	- `Index = 1`, `2`, `3`, `4`, `5`
  	
	### `col2` 값이 있는 행의 개수 세기
	이제 조건에 맞는 행에서 `col2`의 값이 `NULL`이 아닌 경우만 셉니다.
	
	- `Index = 1`: `col2` 값은 `NULL` (카운트 안 함)
	- `Index = 2`: `col2` 값은 `6` (카운트)
	- `Index = 3`: `col2` 값은 `5` (카운트)
	- `Index = 4`: `col2` 값은 `3` (카운트)
	- `Index = 5`: `col2` 값은 `3` (카운트)

  총 `col2` 값이 `NULL`이 아닌 행은 **4개**입니다.
	
	### 정답
	- **4**
  	
	### 해설
	이 쿼리는 조건에 해당하는 행들 중 `col2` 값이 `NULL`이 아닌 행의 개수를 세는 것이 목적입니다. `COUNT(col2)`는 `NULL` 값을 제외하고 개수를 세기 때문에, `col2` 값이 존재하는 행만 카운트하게 됩니다.
	
	- 쿼리에서 `OR` 조건이 사용되었으므로 `col1`이 `2` 또는 `3`이거나 `col2`가 `3` 또는 `5`인 모든 행을 선택합니다.
	- 이후 `COUNT(col2)`는 `col2` 값이 `NULL`이 아닌 행의 개수를 세게 되며, 결과적으로 4개가 됩니다.

	- **두 번째 빈칸**:
	  - **설명**: "( ) 은/는 큰 덩어리의 인터페이스들을 구체적이고 작은 단위들로 분리시킴으로써 클라이언트들이 꼭 필요한 메서드들만 이용할 수 있게 한다."

	따라서, **모든 빈칸**에 들어가야 할 용어는 **인터페이스 분리 원칙 (ISP, Interface Segregation Principle)**입니다.
	
	### 정답
	- **인터페이스 분리 원칙 (ISP, Interface Segregation Principle)**
	
	### 해설
	- **인터페이스 분리 원칙 (ISP)**:
	  - **SOLID 원칙** 중 하나로, 큰 인터페이스를 작은 인터페이스로 나누어 클라이언트가 자신에게 필요하지 않은 메서드에 의존하지 않도록 합니다.
	  - 클라이언트는 자신이 필요로 하는 기능만 가지는 인터페이스에 의존해야 합니다.
	  - 예를 들어, 복합기에서 프린터, 팩스, 복사기를 모두 하나의 큰 인터페이스로 구현하면, 프린터만 사용하는 클라이언트도 팩스나 복사기 메서드에 의존하게 됩니다. 이를 방지하기 위해 각 기능을 분리된 작은 인터페이스로 나누어야 합니다.
	  - **ISP**를 적용하면 각 기능에 대한 변경이 서로에게 영향을 주지 않으며, 클라이언트는 자신이 사용하는 기능만 의존할 수 있습니다.
	
	이와 같은 원칙을 통해 시스템의 결합도를 낮추고 유지보수성을 향상시키며, 소프트웨어 설계를 더 유연하게 만들 수 있습니다.

	### 문제 풀이
	
	주어진 코드:
	
	```java

	  int i = 3; 
	  int k = 1; 
	
	  switch (i) { 
	
	    case 1: k += 1;
	
	    case 2: k++;
	
	    case 3: k = 0; 
	
	    case 4: k += 3;
	```

	- **`case 3:`**: `k = 0`으로 설정됩니다.
	- **`case 4:`**: `k += 3`을 수행합니다. (`k`는 `0 + 3 = 3`이 됩니다)

	- **`default:`**: `k--`를 수행합니다. (`k`는 `-7 - 1 = -8`이 됩니다)
	
	#### 최종 출력
	- `System.out.print(k);`를 통해 `k`의 값인 **`-8`**이 출력됩니다.
	
	### 정답

	- `case 3:`부터 시작하여 이후의 모든 `case`와 `default` 블록이 **연속해서 실행**되기 때문에, `k`의 값이 계속 변경됩니다.
	- 만약 각 `case`에 `break` 문이 있었다면, 해당 `case`만 실행되고 `switch` 블록을 빠져나갔겠지만, 이 코드에서는 그렇지 않기 때문에 이후의 모든 코드가 실행됩니다.

	```java
	class A {
	  int n;
	  int g;
	}
	
	public class Main {
	  public static void main(String[] args) {
	    A[] a = new A[2]; // 객체 배열 선언

	    for (int i = 0; i < 2; i++) {
	```

	   - 반복문에서 `a[i] = new A();`로 각 배열 요소를 객체로 초기화합니다.

	- 반복문에서 객체 배열을 **초기화**하고, 각 필드에 값을 할당한 후 `a[0].n + a[1].g`의 값을 계산합니다.

	주어진 Python 코드를 실행해보고 출력값을 구해보겠습니다.
	
	### 주어진 코드
	```python
	a = "REMEMBER NOVEMBER"
	
	b = a[:3] + a[12:16]
	
	c = "R AND %s" % "STR"

	```
	
	### 코드 분석
	
	#### 1. 변수 `a` 정의
	- `a = "REMEMBER NOVEMBER"`
	  - 문자열 `"REMEMBER NOVEMBER"`가 변수 `a`에 할당됩니다.

	- `b = a[:3] + a[12:16]`

	- `c = "R AND %s" % "STR"`
	  - **포맷 연산자 `%`** 를 사용하여 문자열 `"R AND %s"`에 `"STR"`을 삽입합니다.
	  - 결과적으로 `c`는 `"R AND STR"`가 됩니다.
	
	#### 4. `print(b + c)` 출력
	- `print(b + c)`
	  - `b`는 `"REMMBER"`, `c`는 `"R AND STR"`이므로 `b + c`는 `"REMMBERR AND STR"`입니다.
	
	### 정답
	- **REMMBERR AND STR**

	- **문자열 슬라이싱**: 슬라이싱을 통해 특정 인덱스 범위의 문자열을 추출합니다. `a[:3]`은 처음부터 3번째까지 (`"REM"`), `a[12:16]`은 12번째부터 15번째까지 (`"MBER"`)의 문자입니다.
	- **문자열 포맷팅**: `"R AND %s" % "STR"`은 포맷 연산자를 사용하여 문자열에 값을 삽입합니다.
	- **문자열 덧셈**: `b + c`는 두 문자열을 이어붙이는 결과를 반환합니다.

	이 설명은 **IGP (Interior Gateway Protocol)** 에 해당합니다.
	
	- **IGP (Interior Gateway Protocol)**는 자율 시스템(AS) 내의 네트워크 간에 라우팅 정보를 교환하기 위한 프로토콜입니다. 대표적인 예로 **RIP**와 **OSPF**가 있습니다.
	
	#### 2. 도메인 간 경로 설정 프로토콜 (보안과 제어에 중점)
	- **설명**:
	  - "시스템 사이에 경로 설정 정보 등을 교환하기 위해 사용하는 프로토콜."
	  - 다른 도메인 간 라우팅 시, 빠른 수행보다는 **보안과 제어**가 목적.
	
	이 설명은 **EGP (Exterior Gateway Protocol)** 에 해당합니다.
	
	- **EGP**는 자율 시스템(AS) 간의 라우팅 정보를 교환하기 위해 사용됩니다. 외부 라우팅에 중점을 두고 있으며, **보안과 제어**를 중시합니다.
	
	#### 3. 규모가 큰 네트워크에서 RIP의 단점을 개선한 라우팅 프로토콜
	- **설명**:
	  - "IP 라우팅 프로토콜의 한 종류로, **RIP보다 규모가 큰 네트워크**에서도 사용 가능."
	  - **RIP의 단점을 개선**하고, 자세한 제어와 관리 정보 트래픽 감소를 가능하게 함.
	
	이 설명은 **OSPF (Open Shortest Path First)** 에 해당합니다.
	
	- **OSPF**는 **링크 상태** 기반의 라우팅 프로토콜로, **RIP**의 단점을 보완하고 대규모 네트워크에서도 사용할 수 있습니다. 네트워크의 링크 상태를 기반으로 최적 경로를 계산하며, **RIP**와 비교해 더 빠르고 효율적인 라우팅을 제공합니다.
	
	#### 4. 자율 시스템(AS) 간의 라우팅 정보를 교환하는 외부 게이트웨이 프로토콜
	- **설명**:
	  - "서로 다른 자율 시스템(AS) 간의 라우터 간에 라우팅 정보를 교환하는 데 사용되는 **외부 게이트웨이 프로토콜 (EGP)**."
	  - 네트워크 도달 가능성 정보의 데이터베이스를 유지하며, AS 수준에서 **정책 결정을 실행**함.
	
	이 설명은 **BGP (Border Gateway Protocol)** 에 해당합니다.
	
	- **BGP**는 서로 다른 자율 시스템(AS) 간의 라우팅 정보를 교환하기 위해 사용되는 **외부 라우팅 프로토콜**입니다. 네트워크 도달 가능성 정보를 바탕으로 **AS 연결 그래프**를 구성하고, 이를 통해 **라우팅 루프를 방지**하며 **정책 기반 라우팅**을 수행합니다.
	
	### 정답
	1. **IGP (Interior Gateway Protocol)**
	2. **EGP (Exterior Gateway Protocol)**
	3. **OSPF (Open Shortest Path First)**
	4. **BGP (Border Gateway Protocol)**
	
	### 해설
	- **IGP (Interior Gateway Protocol)**: 자율 시스템 내의 라우터들이 사용하는 경로 설정 프로토콜로, **RIP**, **OSPF** 등이 대표적입니다.
	- **EGP (Exterior Gateway Protocol)**: 자율 시스템 간의 라우팅 정보를 교환하는 프로토콜로, 보안과 제어가 중점입니다.
	- **OSPF (Open Shortest Path First)**: **RIP**의 단점을 개선한 링크 상태 기반 라우팅 프로토콜로, 대규모 네트워크에서 효율적인 라우팅을 제공합니다.
	- **BGP (Border Gateway Protocol)**: 자율 시스템 간 라우팅 정보를 교환하는 데 사용되는 외부 라우팅 프로토콜로, AS 간의 **정책 기반 라우팅**을 수행하고 **라우팅 루프**를 방지합니다.

	#### 2. 성적은 학과만 알아도 식별이 가능하므로, 이 경우에는 성적 속성은 기본키에 ( ) Functional Dependency이다.
	- **설명**: 성적이 **학과**만으로도 결정될 수 있다면, `성적`은 학과에 **부분적으로 종속**되어 있다고 볼 수 있습니다.
	- 기본키가 여러 속성으로 구성된 경우, 기본키의 일부 속성에 종속된 경우를 **부분 함수 종속성 (Partial Functional Dependency)**이라고 합니다.
	
	#### 정답: **부분 함수 종속성 (Partial Functional Dependency)**
	
	#### 3. 릴레이션에서 X, Y, Z라는 3개의 속성이 있을 때 X→Y, Y→Z라는 종속 관계가 있을 경우, X→Z가 성립될 경우
	- **설명**: X가 Y를 결정하고, Y가 Z를 결정한다면, X가 Z를 결정할 수 있는 관계를 **이행적 함수 종속성 (Transitive Functional Dependency)**이라고 합니다.
	- 이행적 함수 종속성은 **중간 단계의 속성**을 통해 종속성을 갖게 되는 경우를 의미합니다.
	
	#### 정답: **이행적 함수 종속성 (Transitive Functional Dependency)**
	
	### 정답 요약
	1. **완전 함수 종속성 (Full Functional Dependency)**
	2. **부분 함수 종속성 (Partial Functional Dependency)**
	3. **이행적 함수 종속성 (Transitive Functional Dependency)**
	
	### 해설
	- **완전 함수 종속성 (Full Functional Dependency)**: 기본키 전체에 의해 결정되는 종속성을 의미합니다. 예를 들어, `{학생, 학과}`가 기본키라면 `성적`은 `{학생, 학과}` 전체에 의해 결정되어야 합니다.
	- **부분 함수 종속성 (Partial Functional Dependency)**: 기본키의 일부 속성만으로 결정될 수 있는 종속성을 의미합니다. 예를 들어, `학과`만으로도 `성적`을 결정할 수 있다면 이는 기본키의 일부에 종속된 것입니다.
	- **이행적 함수 종속성 (Transitive Functional Dependency)**: 중간 단계의 속성을 거쳐 다른 속성과의 종속 관계를 가지는 것을 의미합니다. 예를 들어, `X → Y`이고 `Y → Z`이면 `X → Z`가 성립하며, 이는 이행적 종속입니다.
	
	이를 통해 주어진 문제에서 각 함수 종속성의 유형을 정확하게 이해하고 답을 선택할 수 있습니다.

	주어진 설명을 바탕으로 각 질문에 알맞은 용어를 답으로 작성하겠습니다.
	
	### 문제 풀이
	
	#### 1. 인터넷에서 웹 서버와 사용자의 인터넷 브라우저 사이에 문서를 전송하기 위한 통신 규약
	- **설명**: 
	  - "웹 서버와 인터넷 브라우저 사이에 문서를 전송하기 위한 통신 규약"
	  - "하이퍼텍스트(hypertext) 문서를 교환하기 위한 통신 규약"
	  
	이 설명은 **HTTP (HyperText Transfer Protocol)**에 해당합니다.
	
	- **HTTP**는 **웹 서버와 클라이언트(인터넷 브라우저)** 사이에서 **하이퍼텍스트** 문서를 교환하는 **프로토콜(통신 규약)**입니다. 웹 브라우저에서 웹 페이지를 요청하고 웹 서버에서 응답하는 과정에서 HTTP가 사용됩니다.
	
	#### 2. 하이퍼텍스트를 통한 정보 제공 방법
	- **설명**: 
	  - "문자, 그래픽, 음성, 영상을 하나의 연상 거미집(Web of Association)과 같이 서로 연결시켜 정보를 검색하는 방법"
	  - "링크된 순서에 관계없이 사용자가 원하는 정보를 클릭해 쉽게 접근하는 방식"
	
	이 설명은 **하이퍼텍스트 (Hypertext)**에 해당합니다.
	
	- **하이퍼텍스트**는 여러 개의 **문서나 정보**를 서로 연결하여, 사용자가 **링크를 클릭**함으로써 원하는 정보로 쉽게 이동할 수 있도록 하는 방식입니다. 이는 인터넷에서 웹 페이지 간의 연결을 가능하게 하는 주요한 개념입니다.
	
	#### 3. 웹 페이지 표시를 위한 지배적인 마크업 언어
	- **설명**: 
	  - "웹 페이지 표시를 위해 개발된 지배적인 마크업 언어"
	  - "제목, 단락, 목록 등을 포함한 본문의 구조적 의미를 나타내는 언어"
	
	이 설명은 **HTML (HyperText Markup Language)**에 해당합니다.
	
	- **HTML**은 웹 페이지의 내용을 작성하기 위해 사용되는 **마크업 언어**로, **제목, 단락, 목록, 링크, 인용** 등의 구조적 의미를 정의할 수 있습니다. 웹 브라우저는 HTML로 작성된 페이지를 해석하여 사용자에게 **웹 페이지** 형태로 보여줍니다.
	
	### 정답
	1. **HTTP (HyperText Transfer Protocol)**
	2. **하이퍼텍스트 (Hypertext)**
	3. **HTML (HyperText Markup Language)**
	
	### 해설
	- **HTTP (HyperText Transfer Protocol)**: 인터넷에서 **하이퍼텍스트 문서**를 전송하기 위한 **통신 규약**입니다. 웹 브라우저와 웹 서버 간의 통신에 사용되며, **요청-응답 방식**으로 데이터를 주고받습니다.
	- **하이퍼텍스트 (Hypertext)**: **문자, 이미지, 영상** 등 다양한 정보 요소를 링크로 연결하여 **사용자가 자유롭게 탐색**할 수 있도록 하는 정보 제공 방식입니다. 이는 **인터넷의 핵심 개념**으로, 사용자가 **링크를 통해 정보 간의 연관성**을 따라 이동할 수 있도록 합니다.
	- **HTML (HyperText Markup Language)**: 웹 페이지를 구성하는 **마크업 언어**로, 문서의 구조를 정의하고 **하이퍼텍스트 링크**를 제공하여 다른 페이지나 리소스와 연결할 수 있도록 합니다. **웹 브라우저**는 HTML을 해석하여 사용자에게 **시각적 웹 페이지**를 제공합니다.
