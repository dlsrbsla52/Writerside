#### 1.  다음 Java 코드에서 알맞는 출력 값을 작성하시오.

```java
class Connection {
    private static Connection _inst = null;
    private int count = 0;

    static public Connection get() {
        if(_inst == null) {
            _inst = new Connection();
            return _inst;
        }

        return _inst;
    }

    public void count() {
         count++; 
    }

    public int getCount() {
         return count; 
    }
}

public class main {  
    public static void main(String[] args) {
        Connection conn1 = Connection.get();
        conn1.count();
        Connection conn2 = Connection.get();
        conn2.count();
        Connection conn3 = Connection.get();
        conn3.count();
        conn1.count();
        System.out.print(conn1.getCount());
    }
}
```

- 정답 및 해설
  - 정답 : **`4`**
  - 해설 :
	### 문제 분석:
	
	이 문제는 **싱글톤 패턴(Singleton Pattern)** 을 사용한 Java 프로그램입니다. 싱글톤 패턴은 클래스의 인스턴스를 하나만 생성하여 전역적으로 사용할 수 있도록 하는 디자인 패턴입니다. 이 코드에서는 `Connection` 클래스가 싱글톤으로 구현되어 있습니다.
	
	### 코드 분석:
	
	1. **`Connection` 클래스**:
	   - `private static Connection _inst = null;`: 클래스의 유일한 인스턴스를 가리키는 정적 변수가 선언되어 있습니다.
	   - **`get()` 메서드**: 이 메서드는 `Connection` 클래스의 인스턴스를 반환합니다. 만약 인스턴스가 없다면, 새로운 `Connection` 객체를 생성하여 `_inst`에 할당하고 이를 반환합니다. 이 과정은 싱글톤 패턴을 구현하는 핵심입니다.
	   - **`count()` 메서드**: 이 메서드는 인스턴스 변수 `count`의 값을 증가시키는 역할을 합니다.
	   - **`getCount()` 메서드**: 현재 `count` 값을 반환합니다.
	
	2. **`main` 클래스**:
	   ```java
	   Connection conn1 = Connection.get();
	   conn1.count();
	   Connection conn2 = Connection.get();
	   conn2.count();
	   Connection conn3 = Connection.get();
	   conn3.count();
	   conn1.count();
	   System.out.print(conn1.getCount());
	   ```
	
	   - **`conn1`**: `Connection.get()`을 통해 `conn1`을 생성합니다. 이때 `Connection` 객체가 없으므로 새로운 객체가 생성되고, `count`는 0에서 1로 증가합니다.
	   - **`conn2`**: `Connection.get()`을 호출하면 이미 생성된 인스턴스 `conn1`이 반환됩니다. `conn2`와 `conn1`은 동일한 객체입니다. `count()`를 호출하면 `count`는 1에서 2로 증가합니다.
	   - **`conn3`**: `conn3` 역시 동일한 `Connection` 객체를 참조합니다. `count()`를 호출하면 `count`는 2에서 3으로 증가합니다.
	   - 마지막으로, `conn1.count()`를 다시 호출하면 `count`는 3에서 4로 증가합니다.
	
	3. **`System.out.print(conn1.getCount());`**:
	   - `conn1.getCount()`는 현재의 `count` 값을 반환합니다. 이때 `count`는 4로 설정되어 있습니다.
	
	### 최종 출력:
	```java
	4
	```
	
	### 해설:
	- 이 코드는 **싱글톤 패턴**을 구현하여 `Connection` 클래스의 인스턴스가 하나만 생성되도록 합니다.
	- `conn1`, `conn2`, `conn3` 모두 동일한 `Connection` 객체를 참조하므로, `count()` 메서드를 호출할 때마다 같은 객체의 `count` 값이 증가합니다.
	- 최종적으로 `count` 값은 4가 되어, 출력값은 **`4`** 입니다.








#### 2. 다음 C언어 코드에서 알맞는 출력 값을 작성하시오.

```C
#include <stdio.h>
int main() {
    int v1 = 0, v2 = 35, v3 = 29;
    if(v1 > v2 ? v2 : v1) {
        v2 = v2 << 2;
    }else{
        v3 = v3 << 2;
    }
    printf("%d", v2+v3);
}
```


- 정답 및 해설 :
  - 정답 : **`151`**
  - 해설 :
	### 문제 분석:
	
	주어진 C 코드는 삼항 연산자와 비트 시프트 연산자를 활용하여 특정 조건에 따라 변수 값을 변경한 후, 그 결과를 출력하는 프로그램입니다.
	
	### 코드 분석:
	
	#### 1. 변수 초기화:
	```c
	int v1 = 0, v2 = 35, v3 = 29;
	```
	- `v1 = 0`
	- `v2 = 35`
	- `v3 = 29`
	
	#### 2. 조건문 (`if`문):
	```c
	if(v1 > v2 ? v2 : v1) {
	    v2 = v2 << 2;
	}else{
	    v3 = v3 << 2;
	}
	```
	- 삼항 연산자: `v1 > v2 ? v2 : v1`
	  - **`v1 > v2`** 는 **`false`** (`0 > 35`가 거짓).
	  - 따라서 삼항 연산자는 **`v1`** 을 반환합니다. 즉, `v1 = 0`이 선택됩니다.
	
	- 조건문: `if(v1)`는 **`if(0)`** 와 같기 때문에 조건이 **거짓**이 됩니다.
	  - 따라서 `else` 블록이 실행됩니다.
	
	#### 3. `else` 블록 실행:
	```c
	v3 = v3 << 2;
	```
	- `v3`는 **비트 시프트 연산**에 의해 왼쪽으로 2비트 이동합니다.
	  - `v3 = 29 << 2`
	  - `29`의 2진수는 `11101`이며, 2비트 왼쪽으로 이동하면 `1110100`이 됩니다. 이는 10진수로 **116**입니다.
	  - 따라서 `v3 = 116`.
	
	#### 4. 최종 출력:
	```c
	printf("%d", v2 + v3);
	```
	- `v2`는 변하지 않고 여전히 **35**입니다.
	- `v3`는 **116**으로 변경되었습니다.
	- 따라서 `v2 + v3 = 35 + 116 = 151`.
	
	### 최종 출력값:
	```c
	151
	```
	
	### 해설:
	- 삼항 연산자를 사용한 조건문에서 `v1` 값이 `0`이므로, 조건이 거짓으로 평가되어 `else` 블록이 실행됩니다.
	- `v3`는 왼쪽으로 2비트 이동하여 값이 **116**으로 바뀌고, `v2`는 변경되지 않아 **35**입니다.
	- 따라서 최종 출력값은 **151**입니다.








#### 3. 다음은 응집도와 관련해서 보기에서 응집도가 높은 순으로 나열하시오.


보기

| ㄱ. 기능                   ㄴ. 교환                             ㄷ. 우연                             ㄹ. 시간 |
| ------------------------------------------------------------------------------------------------- |


- 정답 및 해설
  - 정답 : ㄱ > ㄴ > ㄹ >ㄷ
  - 해설 :
	### 정답: **ㄱ. 기능 > ㄴ. 교환 > ㄹ. 시간 > ㄷ. 우연**
	
	---
	
	### 해설:
	
	**응집도(Cohesion)** 는 모듈 내의 요소들이 얼마나 밀접하게 연관되어 있는지를 나타내는 척도입니다. 응집도가 높을수록 모듈의 각 구성 요소가 명확한 목적을 가지고 서로 잘 연결되어 있으며, 응집도가 낮을수록 모듈 내의 요소들이 서로 관련 없이 혼합되어 있다는 의미입니다.
	
	응집도는 높은 것이 바람직하며, 모듈의 유지보수성과 재사용성을 높여줍니다. 응집도는 여러 유형으로 나눌 수 있으며, 아래는 응집도의 종류와 그 순서입니다:
	
	### 1. **기능적 응집도 (Functional Cohesion)**:
	   - **설명**: 모듈이 **하나의 기능**만을 수행하는 경우로, 가장 이상적이고 높은 응집도를 가진다.
	   - **예시**: 한 함수가 단일한 작업(예: 파일 읽기)을 수행하는 경우.
	   - **응집도**: 가장 높음.
	
	### 2. **교환적 응집도 (Communicational Cohesion)**:
	   - **설명**: 모듈이 **같은 데이터**를 사용하는 여러 작업을 포함하는 경우.
	   - **예시**: 동일한 데이터 구조를 처리하는 여러 작업이 하나의 모듈에 포함된 경우.
	   - **응집도**: 기능적 응집도보다는 낮지만 여전히 높은 응집도를 가짐.
	
	### 3. **시간적 응집도 (Temporal Cohesion)**:
	   - **설명**: 모듈 내의 기능들이 **특정 시간대**에 실행되도록 묶인 경우.
	   - **예시**: 시스템 초기화 과정에서 여러 작업(로그 설정, 파일 초기화 등)이 함께 수행되는 경우.
	   - **응집도**: 교환적 응집도보다 낮음.
	
	### 4. **우연적 응집도 (Coincidental Cohesion)**:
	   - **설명**: 모듈 내의 기능들이 **서로 관련 없이** 단순히 묶인 경우로, 응집도 중에서 가장 낮다.
	   - **예시**: 무작위로 모여 있는 기능들이 하나의 모듈에 들어가 있는 경우.
	   - **응집도**: 가장 낮음.
	
	---
	
	### 결론:
	
	응집도가 높은 순서대로 나열하면 **기능적 > 교환적 > 시간적 > 우연적**이므로, 보기의 항목을 정리하면:
	
	**ㄱ. 기능 > ㄴ. 교환 > ㄹ. 시간 > ㄷ. 우연**
	
	이 순서가 응집도가 높은 순서입니다.








#### 4. 다음은 C언어에 대한 문제이다. 알맞는 출력 값을 작성하시오.

```C
#include <stdio.h>
#include <string.h>

void reverse(char* str){
    int len = strlen(str);
    char temp;
    char *p1 = str;
    char *p2 = str + len - 1;

    while(p1<p2){
        temp = *p1;
        *p1 = *p2;
        *p2 = temp;
        p1++;
        p2--;
    }

}

int main(int argc, char* argv[]){
    char str[100] = "ABCDEFGH";
    
    reverse(str);

    int len = strlen(str);

    for(int i=1; i<len; i+=2){
        printf("%c",str[i]);
    }

    printf("\n");
    return 0;
}
```


- 정답 및 해설
  - 정답 : **`GECA`**
  - 해설 :
	### 문제 분석:
	
	이 C 프로그램은 다음과 같은 작업을 수행합니다:
	1. 문자열을 뒤집는 함수 `reverse`를 통해 입력 문자열을 역순으로 만듭니다.
	2. 역순으로 된 문자열에서 **짝수 인덱스**의 문자들을 출력합니다.
	
	### 코드 분석:
	
	#### 1. **`reverse` 함수**:
	```c
	void reverse(char* str){
	    int len = strlen(str);
	    char temp;
	    char* p1 = str;
	    char* p2 = str + len - 1;
	
	    while(p1 < p2){
	        temp = *p1;
	        *p1 = *p2;
	        *p2 = temp;
	        p1++;
	        p2--;
	    }
	}
	```
	- 이 함수는 문자열을 뒤집는 역할을 합니다. `p1`은 문자열의 첫 번째 문자를, `p2`는 마지막 문자를 가리킵니다. 두 포인터가 서로 교차할 때까지, `p1`과 `p2`가 가리키는 문자를 서로 교환하며 문자열을 역순으로 만듭니다.
	- 주어진 입력 문자열이 `"ABCDEFGH"`라면, 이 함수가 호출된 후에는 문자열이 `"HGFEDCBA"`로 바뀝니다.
	
	#### 2. **`main` 함수**:
	```c
	int main(int argc, char* argv[]){
	    char str[100] = "ABCDEFGH";
	    
	    reverse(str);
	    
	    int len = strlen(str);
	
	    for(int i = 1; i < len; i += 2){
	        printf("%c", str[i]);
	    }
	
	    printf("\n");
	    return 0;
	}
	```
	- **`reverse(str)`** 호출로 인해 `str`은 `"HGFEDCBA"`로 변환됩니다.
	- **`for` 루프**는 인덱스 1부터 시작하여 2씩 증가하면서 짝수 인덱스(1, 3, 5, 7)의 문자를 출력합니다.
	
	#### 3. **출력되는 문자**:
	- 역순으로 된 문자열은 `"HGFEDCBA"`입니다.
	- 이 중에서 짝수 인덱스의 문자는:
	  - `str[1] = 'G'`
	  - `str[3] = 'E'`
	  - `str[5] = 'C'`
	  - `str[7] = 'A'`
	
	따라서 출력되는 문자열은 **`GECA`** 입니다.
	
	### 최종 출력값:
	```c
	GECA
	```
	
	### 해설:
	- 프로그램은 먼저 문자열 `"ABCDEFGH"`을 역순으로 변환하여 `"HGFEDCBA"`로 만듭니다.
	- 그 후 짝수 인덱스에 해당하는 문자들(`G`, `E`, `C`, `A`)를 차례대로 출력하여 최종 출력값은 **`GECA`** 가 됩니다.

	1. **모든 분기와 조건의 조합을 고려하나 모든 조합을 테스트하는 대신에 테스트가 필요한 중요한 조합을 찾아내는데 중점을 둔다**:
	   - **MC/DC**는 **모든 조합을 테스트하지 않고** 중요한 조합만 선택하여 테스트합니다. 이는 모든 가능한 조합을 테스트하기에 비용이 많이 들기 때문에, 테스트 효율성을 높이기 위해 꼭 필요한 조합을 선택하는 방식입니다.

	   - **MC/DC**는 **각각의 조건이 전체 결과에 미치는 영향을 독립적으로 테스트**합니다. 즉, 특정 조건이 결과에 영향을 줄 때, 다른 조건들은 상관없이 테스트됩니다.
	
	3. **각각의 파라미터는 적어도 한 번은 최종 결과에 영향을 주어야 한다**:
	   - **MC/DC**는 각 조건이 최소 한 번은 결과에 영향을 주도록 테스트합니다. 이는 모든 조건이 적어도 한 번은 테스트되도록 보장합니다.
	
	---

	- **구문 커버리지**: 코드 내 모든 구문이 최소한 한 번 실행되었는지를 검사하는 기법.
	- **결정 커버리지**: 모든 분기점(조건문의 true/false 결과)이 최소한 한 번씩 실행되었는지 테스트하는 기법.
	- **조건 커버리지**: 개별 조건이 최소한 한 번 true, 한 번 false가 되는지 확인하는 기법.
	- **다중 조건 커버리지**: 모든 조건과 그 조합을 테스트하는 기법.
	- **경로 커버리지**: 코드 내의 모든 경로를 테스트하는 기법.
	- **조건/결정 커버리지**: 조건과 결정을 함께 고려하여 테스트하는 기법.
	
	---
	
	### 결론:
	
	- **변경 조건/결정 커버리지 (MC/DC)** 는 **중요한 조건 조합만을 테스트**하고, 각각의 조건이 독립적으로 결과에 영향을 주도록 테스트하는 방식입니다.

	3. **다양한 시스템 영역에서 작동**:
	   - 루트킷은 펌웨어, 가상화 계층, 운영체제 커널 등 다양한 시스템 영역에서 동작할 수 있으며, **시스템을 완전히 장악**할 수 있습니다.
	
	---
	
	### 보기 설명:
	
	- **ㄱ. Worm (웜)**: 네트워크를 통해 스스로 복제되며 퍼지는 악성 프로그램.
	- **ㄴ. Trojan horse (트로이 목마)**: 겉으로는 정상적인 프로그램처럼 보이지만, 내부에 악성 코드를 숨겨놓은 프로그램.
	- **ㄷ. Backdoor (백도어)**: 공격자가 시스템에 몰래 설치하여 비밀리에 접근할 수 있도록 하는 프로그램.
	- **ㄹ. Virus (바이러스)**: 사용자 파일을 감염시키고, 파일 복사 등을 통해 확산되는 악성 프로그램.
	- **ㅁ. Ransomware (랜섬웨어)**: 사용자의 파일을 암호화하고, 이를 풀기 위한 대가로 금전을 요구하는 악성 프로그램.
	- **ㅂ. Spyware (스파이웨어)**: 사용자의 정보를 몰래 수집하는 프로그램.
	- **ㅅ. Rootkit (루트킷)**: 시스템에 대한 제어권을 유지하면서 자신을 숨기는 악성 프로그램.
	
	---
	
	### 결론:
	
	**Rootkit**은 시스템 깊숙한 부분에서 작동하면서 해커의 존재를 숨기고, 시스템에 대한 제어권을 유지하는 도구입니다.

```C
#include<stdio.h>
#include<ctype.h>

int main(){
    char*p = "It is 8";
    char result[100];
    int i;

    for(i=0; p[i]!='\0'; i++){
        if(isupper(p[i]))
            result[i] = (p[i]-'A'+5)% 25 + 'A';
        else if(islower(p[i]))
            result[i] = (p[i]-'a'+10)% 26 + 'a';
        else if(isdigit(p[i]))
            result[i] = (p[i]-'0'+3)% 10 + '0';
        else if(!(isupper(p[i]) || islower(p[i]) || isdigit(p[i])))    
            result[i] = p[i];
    }

    result[i] = '\0';
    printf("%s\n",result);
    return 0;
}
```


- 정답 및 해설
  - 정답 : `Nd sc 1`
  - 해설 :
	### 문제 분석:
	
	주어진 C 코드에서는 문자열 `"It is 8"`을 특정 규칙에 따라 변환하고 결과를 출력합니다. 이 규칙은 문자와 숫자를 변환하는 방식으로, 대문자, 소문자, 숫자에 각각 다른 연산을 적용합니다.
	
	---
	
	### 코드 분석:
	
	1. **`char *p = "It is 8";`**: 문자열 `"It is 8"`을 포인터 `p`로 가리키고 있습니다.
	
	2. **`for` 루프**: 이 루프는 문자열의 각 문자를 순차적으로 처리하며, 조건에 따라 변환된 값을 `result` 배열에 저장합니다.
	   
	3. **조건별 변환 규칙**:
	   
	   - **대문자(`isupper(p[i])`)**:
	     ```c
	     result[i] = (p[i] - 'A' + 5) % 25 + 'A';
	     ```
	     - 대문자는 `'A'`에서의 오프셋을 기준으로 5를 더한 후, 25로 나눈 나머지에 다시 `'A'`를 더해 새로운 대문자로 변환됩니다.
	   
	   - **소문자(`islower(p[i])`)**:
	     ```c
	     result[i] = (p[i] - 'a' + 10) % 26 + 'a';
	     ```
	     - 소문자는 `'a'`에서의 오프셋을 기준으로 10을 더한 후, 26으로 나눈 나머지에 다시 `'a'`를 더해 새로운 소문자로 변환됩니다.
	
	   - **숫자(`isdigit(p[i])`)**:
	     ```c
	     result[i] = (p[i] - '0' + 3) % 10 + '0';
	     ```
	     - 숫자는 `'0'`에서의 오프셋을 기준으로 3을 더한 후, 10으로 나눈 나머지에 다시 `'0'`을 더해 새로운 숫자로 변환됩니다.
	
	   - **기타 문자** (공백이나 특수 문자 등):
	     - 공백이나 다른 특수 문자는 변환되지 않고 그대로 `result`에 저장됩니다.
	   
	4. **종료**:
	   - 문자열의 마지막에 `\0`을 추가하여 문자열의 끝을 나타냅니다.
	   
	5. **출력**:
	   - 변환된 결과 문자열을 출력합니다.
	
	---
	
	### 변환 과정:
	
	문자열 `"It is 8"`을 변환하는 과정을 살펴보겠습니다:
	
	1. **`'I'` (대문자)**:
	   - `(p[i] - 'A' + 5) % 25 + 'A' = ('I' - 'A' + 5) % 25 + 'A' = (8 + 5) % 25 + 'A' = 13 + 'A' = 'N'`
	   - 결과: **`'N'`**
	
	2. **`'t'` (소문자)**:
	   - `(p[i] - 'a' + 10) % 26 + 'a' = ('t' - 'a' + 10) % 26 + 'a' = (19 + 10) % 26 + 'a' = 29 % 26 + 'a' = 3 + 'a' = 'd'`
	   - 결과: **`'d'`**
	
	3. **공백 (`' '`)**:
	   - 공백은 변환되지 않고 그대로 유지됩니다.
	   - 결과: **`' '`**
	
	4. **`'i'` (소문자)**:
	   - `(p[i] - 'a' + 10) % 26 + 'a' = ('i' - 'a' + 10) % 26 + 'a' = (8 + 10) % 26 + 'a' = 18 + 'a' = 's'`
	   - 결과: **`'s'`**
	
	5. **`'s'` (소문자)**:
	   - `(p[i] - 'a' + 10) % 26 + 'a' = ('s' - 'a' + 10) % 26 + 'a' = (18 + 10) % 26 + 'a' = 28 % 26 + 'a' = 2 + 'a' = 'c'`
	   - 결과: **`'c'`**
	
	6. **공백 (`' '`)**:
	   - 공백은 변환되지 않고 그대로 유지됩니다.
	   - 결과: **`' '`**
	
	7. **`'8'` (숫자)**:
	   - `(p[i] - '0' + 3) % 10 + '0' = ('8' - '0' + 3) % 10 + '0' = (8 + 3) % 10 + '0' = 11 % 10 + '0' = 1 + '0' = '1'`
	   - 결과: **`'1'`**
	
	---
	
	### 최종 변환된 결과:
	
	**`"Nd sc 1"`**
	
	---
	
	### 최종 출력값:
	
	```
	Nd sc 1
	```
	
	---
	
	### 해설:
	
	- 대문자는 5만큼 이동, 소문자는 10만큼 이동, 숫자는 3만큼 이동하여 변환되었습니다.
	- 공백은 그대로 유지되었습니다.




#### 20. 다음 아래의 내용을 보고 알맞는 용어를 작성하시오. 

구체적인 클래스에 의존하지 않고 서로 연관되거나 의존적인 객체들의 조합을 만드는 인터페이스를 제공하는 패턴이다.  
연관성이 있는 객체 군이 여러개 있을 경우 이들을 묶어 추상화하고, 어떤 구체적인 상황이 주어지면 팩토리 객체에서 집합으로 묶은 객체 군을 구현화 하는 생성 패턴이다  
관련성 있는 여러 종류의 객체를 일관된 방식으로 생성하는 경우에 유용하다.  
kit라고도 불린다.



- 정답 및 해설
  - 정답: **Abstract Factory (추상 팩토리 패턴)**
  - 해설:
	주어진 설명은 **추상 팩토리 패턴 (Abstract Factory Pattern)**에 대한 설명입니다. 이 패턴은 **구체적인 클래스에 의존하지 않고, 서로 연관되거나 의존적인 객체들의 조합을 만드는 인터페이스를 제공**하는 생성 패턴입니다. 이제 설명에 나오는 각각의 요소를 분석해 보겠습니다.
	
	---
	
	### 설명 분석:
	
	1. **구체적인 클래스에 의존하지 않고 서로 연관되거나 의존적인 객체들의 조합을 만드는 인터페이스를 제공하는 패턴**:
	   - **추상 팩토리 패턴**은 객체를 직접 생성하는 것이 아니라, **추상화된 인터페이스**를 통해 서로 연관된 객체들을 생성하는 역할을 합니다. 이로 인해 **구체적인 클래스에 의존하지 않고** 객체들의 조합을 만들 수 있습니다.
	
	2. **연관성이 있는 객체 군이 여러 개 있을 경우, 이들을 묶어 추상화하고, 어떤 구체적인 상황이 주어지면 팩토리 객체에서 집합으로 묶은 객체 군을 구현화하는 생성 패턴**:
	   - **추상 팩토리 패턴**은 **서로 연관된 객체들의 집합을 생성**하는 역할을 합니다. 즉, 연관된 여러 종류의 객체들을 함께 묶어 한 번에 생성할 수 있으며, 이는 특정한 **구체적인 상황에 맞춰서 구현화**됩니다.
	
	3. **관련성 있는 여러 종류의 객체를 일관된 방식으로 생성하는 경우에 유용**:
	   - 이 패턴은 **서로 관련된 객체들을 일관성 있게 생성**할 필요가 있을 때 유용합니다. 예를 들어, 여러 종류의 버튼, 창 등을 사용하는 GUI 시스템에서 다양한 테마를 적용할 때 사용됩니다.
	
	4. **Kit이라고도 불린다**:
	   - **추상 팩토리 패턴**은 **"Kit"** 으로 불리기도 합니다. 여러 개의 관련 객체들을 하나의 세트로 묶어 제공하는 방식이기 때문입니다.
	
	---
	
	### 추상 팩토리 패턴의 특징:
	
	- **객체 생성에 있어 인터페이스를 통해 구현을 감추는 방식**입니다.
	- **구체적인 클래스에 의존하지 않고** 연관된 객체들을 생성할 수 있습니다.
	- **서로 관련된 객체들을 일관성 있게 생성**할 수 있도록 합니다.
	- **팩토리 메서드 패턴**과는 다르게, 연관된 객체들을 **세트로 생성**할 수 있습니다.
	
	---
	
	### 결론:
	
	**Abstract Factory (추상 팩토리 패턴)** 는 구체적인 클래스를 알 필요 없이, **연관된 객체 군을 일관된 방식으로 생성하는**데 매우 유용한 패턴입니다.
