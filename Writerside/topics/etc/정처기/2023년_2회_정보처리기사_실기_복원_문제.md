#### 5. 다음은 C언어의 문제이다. 알맞은 출력값을 작성하시오.


```c
int n[3] = [73, 95, 82] 

sum = 0 

for(i=0;i<3;i++){
    sum += n[i];
}

switch(sum/30){
    case 10:
    case 9: printf("A");
    case 8: printf("B");
    case 7: 
    case 6: printf("C");
    default: printf("D");
}
```


- 정답 및 해설
  - 정답 : ABCD
  - 해설

	주어진 C 코드에서의 흐름을 따라가며 문제를 분석하겠습니다.
	
	#### 코드 설명:
	
	1. **변수 초기화:**
	   ```c
	   int n[3] = [73, 95, 82]; // 잘못된 배열 초기화 방식
	   ```
	   사실, 배열 초기화는 `[ ]`가 아니라 `{ }`를 사용해야 하므로 다음과 같이 수정되어야 합니다:
	   ```c
	   int n[3] = {73, 95, 82};
	   ```
	   
	2. **합 계산:**
	   ```c
	   sum = 0;
	   for (i = 0; i < 3; i++) {
	       sum += n[i];
	   }
	   ```
	   - 배열 `n`의 값들을 더합니다:
	     - `73 + 95 + 82 = 250`
	   - 따라서 `sum = 250`입니다.
	
	3. **switch 문에서의 동작:**
	   ```c
	   switch (sum / 30) {
	       case 10:
	       case 9:  printf("A");
	       case 8:  printf("B");
	       case 7:
	       case 6:  printf("C");
	       default: printf("D");
	   }
	   ```
	   - `sum / 30 = 250 / 30 = 8` (정수 나눗셈이므로 몫만 남습니다)
	   - 따라서 `switch (8)`로 진행됩니다.
	   
	   **case 8:부터 실행:**
	   - `case 8`에 해당하므로 `"B"`가 출력됩니다.
	   - 이후 `break` 문이 없으므로 다음 코드들이 모두 실행됩니다:
	     - `"C"`가 출력됩니다 (`case 6`).
	     - `"D"`가 출력됩니다 (`default`).
	   
	   따라서 최종 출력 결과는: `"ABCD"`입니다.
	
	#### 출력 요약:
	
	```
	ABCD
	```
	
	**참고:** `switch` 문에서 `break`가 없을 경우, 해당 `case`에 매칭된 이후 나머지 `case`와 `default` 구문이 모두 실행되는 **fall-through** 현상이 발생합니다. 이 문제의 경우에도 `break`가 없기 때문에 `"B"`, `"C"`, `"D"`가 순서대로 출력됩니다.

	- 조건 커버리지는 개별 조건의 참과 거짓 결과를 테스트하지만, 모든 조건의 조합을 고려하지는 않기 때문에 **충분한 영향을 줄 수 없는 한계**가 있습니다.

	   - **정답**: **CRC**
	   - **설명**: (5)번 문제는 **전송된 데이터에 오류가 있는지를 확인하기 위한 체크값을 결정하는 방식**에 관한 것이었으며, 이는 **CRC (Cyclic Redundancy Check)** 에 해당합니다.

#### 13. 다음은 HDLC 프로토콜에 대한 설명이다. 보기 안에 알맞는 답을 골라 작성하시오.

( 1 ) 프레임은 Seq, Next, P/F의 필드를 가진다. 또한 맨 처음 비트를 0으로 가진다. Seq는 송신용 순서번호를 가지고 있다. Next는 응답용 순서번호를 가진다. P/F는 P가 1로 설정된 경우 주국에서 종국에 데이터 전송을 허용하는 것을 의미하고 F가 1로 설정된 경우 종국에서 주국으로 데이터 전송을 하는 것을 의미한다.

( 3 ) 프레임은 순서 번호가 없는 프레임을 의미한다. 첫 번째 비트와 두 번째 비트가 모두 1로 설정되어 있다. 여러 종류를 가지고 있는데 Type의 2비트와 Modifier의 3비트를 합쳐 5비트를 통해 종류를 나눈다.
  
( 4 ) 은/는 두 호스트 모두 혼합국으로 동작한다. 양쪽에서 명령과 응답을 전송할 수 있다.

  - 정답 :

  - 해설
	
	암호화 알고리즘은 **대칭키 암호화(Symmetric Key Encryption)** 와 **비대칭키 암호화(Asymmetric Key Encryption)** 로 나뉩니다.
	
	### 1. **대칭키 암호화 (Symmetric Key Encryption)**:
	
	- **대칭키 암호화**에서는 암호화와 복호화에 **동일한 키**를 사용합니다. 즉, 송신자와 수신자가 같은 비밀키를 공유하여 데이터를 암호화하고 복호화합니다.
	- **대칭키 암호화**는 **빠른 속도**로 데이터를 암호화할 수 있다는 장점이 있지만, 키의 분배와 관리가 어렵다는 단점이 있습니다.
	
	**대칭키 알고리즘**:
	- **DES (Data Encryption Standard)**: 초기의 대칭키 암호화 알고리즘으로, 이제는 보안성이 낮아 잘 사용되지 않습니다.
	- **AES (Advanced Encryption Standard)**: 현재 가장 널리 사용되는 대칭키 암호화 알고리즘으로, **고속성과 보안성**을 갖춘 강력한 알고리즘입니다.
	- **ARIA**: 한국에서 개발된 대칭키 암호화 알고리즘으로, 안전성과 성능이 입증되어 다양한 분야에 사용됩니다.
	- **SEED**: 한국에서 개발된 또 다른 대칭키 암호화 알고리즘으로, 금융과 같은 분야에서 사용됩니다.
	
	따라서, **대칭키**에 해당하는 알고리즘은 **DES, AES, ARIA, SEED**입니다.
	
	### 2. **비대칭키 암호화 (Asymmetric Key Encryption)**:
	
	- **비대칭키 암호화**는 **공개키**와 **개인키**라는 두 개의 키를 사용합니다. 공개키는 모든 사람과 공유할 수 있고, 개인키는 비밀로 유지합니다.
	- 공개키로 암호화한 데이터는 개인키로만 복호화할 수 있으며, 개인키로 암호화한 데이터는 공개키로 복호화할 수 있습니다.
	- **비대칭키 암호화**는 **키의 분배**가 용이하고 보안성이 뛰어나지만, 대칭키 암호화에 비해 **암호화 속도가 느리다는** 단점이 있습니다.
	
	**비대칭키 알고리즘**:
	- **RSA (Rivest–Shamir–Adleman)**: 가장 널리 알려진 비대칭키 암호화 알고리즘입니다. 큰 소수를 이용한 수학적 연산에 기반하며, 공개키와 개인키를 사용합니다.
	- **ECC (Elliptic Curve Cryptography)**: 타원 곡선을 이용한 비대칭키 암호화 알고리즘입니다. **RSA**보다 더 짧은 키 길이로 비슷한 수준의 보안을 제공하므로, **경량화된 환경**에서 많이 사용됩니다.
	
	따라서, **비대칭키**에 해당하는 알고리즘은 **RSA, ECC**입니다.
	
	### 정리:
	
	- **대칭키**: **DES, AES, ARIA, SEED**
	- **비대칭키**: **RSA, ECC**
	
	대칭키는 **속도가 빠르고 키의 관리가 어렵다**는 특징이 있으며, 비대칭키는 **보안성이 높지만 속도가 느리다**는 특징이 있습니다.

  - 해설

	1. **"임의의 크기를 가진 데이터(Key)를 고정된 크기의 데이터(Value)로 변화시켜 저장하는 것이다."**
	    - **해시(Hash)**는 임의의 크기를 가진 데이터를 고정된 크기의 값으로 변환합니다. 이때 데이터(Key)를 고정된 길이의 데이터(Value)로 매핑하여 저장할 수 있습니다. 이를 통해 데이터 검색이 용이해집니다.
	      
	1. **"키에 대한 해시 값을 사용하여 값을 저장하고 키-값 쌍의 갯수에 따라 동적으로 크기가 증가한다."**

	4. **"해시 함수는 임의의 길이의 데이터를 고정된 길이의 데이터로 매핑하는 함수이다."**
	    - **해시 함수(Hash Function)** 는 임의의 크기를 가진 데이터를 **고정된 크기의 해시 값**으로 변환하는 역할을 합니다. 해시 함수의 출력은 항상 고정된 크기입니다.
	      
	5. **"해시 함수는 큰 파일에서 중복되는 레코드를 찾을 수 있기 때문에 데이터베이스 검색이나 테이블 검색의 속도를 가속할 수 있다."**
	    - **해시 함수**는 큰 파일에서 **중복 레코드** 를 찾거나, 데이터베이스나 테이블의 **검색 속도**를 높이는 데 매우 유용합니다. 데이터의 **중복 확인**이나 **빠른 검색**을 가능하게 해줍니다.
	
	### 요약:
	
	- **해시(Hash)** 는 임의의 데이터를 고정된 크기로 변환하여 저장하는 방식입니다.
	- 해시 테이블은 **해시 함수**를 이용해 데이터를 빠르게 저장하고 검색하는 구조이며, **평균 시간복잡도 O(1)** 로 효율적입니다.
	- **해시 함수**는 데이터베이스에서 중복 레코드를 찾고, 검색 속도를 가속하는 데 중요한 역할을 합니다.
	
	따라서, 모든 괄호에 들어갈 답은 **해시(Hash)** 가 맞습니다.
