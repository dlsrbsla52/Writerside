#### 1. 다음은 java 코드에 대한 문제이다. 아래 코드를 확인하여 알맞는 출력값을 작성하시오.
```java
class Main {

    public static void main(String[] args) {
        int[] a = new int[]{1, 2, 3, 4};
        int[] b = new int[]{1, 2, 3, 4};
        int[] c = new int[]{1, 2, 3};

		check(a, b);
        check(a, c); 
        check(b, c); 
    }

    public static void check(int[] a, int[] b) {
        if (a==b) {
            System.out.print("O");
        }else{
            System.out.print("N");
        }
    }
}
```

- 정답 및 해설
   - 정답 : NNN
   - 해설 : Java 코드의 출력이 `NNN`인 이유는 자바에서 배열을 비교할 때, 배열의 **참조(reference)** 를 비교하기 때문.
   `a == b`는 두 배열이 같은 메모리 위치를 참조하고 있는지를 확인하는 연산으로,  배열의 내용이 동일하더라도 다른 메모리에 저장된 두 배열의 참조는 다르므로 `a == b`는 `false`가 된다.
   1. `int[] a = new int[]{1, 2, 3, 4};` 
   2. `int[] b = new int[]{1, 2, 3, 4};`
  위 두 줄은 배열의 내용은 같지만, 각각 새로운 배열을 생성하므로 서로 다른 메모리 주소를 참조함. 따라서 `a == b`는 `false`가 되어 `N`이 출력.

데이터를 중복시켜 성능을 향상시키기 위한 기법으로 데이터를 중복 저장하거나, 테이블을 합치는 등으로 성능을 향상시키지만 데이터 무결성이 저하될 수 있는 기법
- 정답 및 해설:
  - 정답 : 반정규화
  - 해설 : **비정규화(Denormalization)** 란?
	  비정규화는 데이터베이스 성능을 최적화하기 위해 **데이터를 중복 저장하거나 테이블을 합치는 방식**으로 데이터를 관리하는 기법입니다. 이를 통해 **데이터베이스 쿼리 성능을 높일 수 있지만**, 그 결과로 데이터 **무결성**이 저하될 가능성이 있습니다.
	  ##### 특징:
	1. **성능 향상**:
	- 쿼리 시 **조인(Join) 연산**을 줄이거나, 불필요한 계산을 피할 수 있어서 **응답 시간이 빨라지고 성능이 개선**됩니다.
	- 주로 읽기 성능을 향상시키기 위해 사용됩니다.
	2. **데이터 무결성 저하**:
	- 데이터를 중복 저장하게 되면, 데이터가 여러 곳에 분산되어 일관성을 유지하기 어려울 수 있습니다.
	- 데이터 변경 시 **모든 중복된 데이터가 일관되게 수정**되지 않으면, **데이터 무결성 문제가 발생**할 수 있습니다.
	3. **관리 비용 증가**:
	- 비정규화된 데이터베이스는 중복된 데이터로 인해 업데이트 시 더 많은 수정이 필요하므로, 유지보수 및 관리가 더 복잡해질 수 있습니다.
	###### 비정규화의 예:
	- **정규화된 데이터베이스**에서는 데이터를 중복 없이 여러 테이블에 나눠서 저장하여 데이터의 일관성과 무결성을 보장합니다.
	- 반면, **비정규화된 데이터베이스**에서는 성능을 높이기 위해 중복 데이터를 허용하고, 테이블을 결합하여 불필요한 조인을 줄입니다.
	비정규화는 읽기 성능이 중요한 시스템(예: 데이터 분석 시스템)에서 자주 사용되며, 무결성보다 성능이 더 중요한 경우 선택하는 전략입니다.

#### 5. 다음은 프로토콜에 대한 내용이다. 아래 내용을 읽고 알맞는 답을 작성하시오.

- Network layer에서 IP패킷을 암호화하고 인증하는 등의 보안을 위한 표준이다. 
- 기업에서 사설 인터넷망으로 사용할 수 있는 VPN을 구현하는데 사용되는 프로토콜이다.  
- AH(Authentication Header)와 ESP(Encapsulating Security Payload)라는 두 가지 보안 프로토콜을 사용한다.

- 정답 및 해설 :
  정답 : IPSec
  - 해설 : 
    **IPSec (Internet Protocol Security)** 는 네트워크 통신에서 데이터를 안전하게 전송하기 위한 표준 프로토콜입니다. IPSec은 IP 계층에서 작동하며, 데이터의 기밀성, 무결성, 인증을 보장하는 데 사용됩니다. 주로 가상 사설망(VPN, Virtual Private Network)이나 보안이 중요한 네트워크 연결에 사용됩니다.
	  ###### IPSec의 주요 기능:
	
	1. **기밀성 (Confidentiality)**:
	    - 데이터를 암호화하여 전송 중에 제3자가 데이터를 읽지 못하도록 보호합니다. **대칭 키 암호화 방식**(예: AES, 3DES)을 사용하여 데이터를 암호화합니다.
	1. **무결성 (Integrity)**:
	    - 데이터가 전송 중에 변경되지 않았음을 보장합니다. 이를 위해 **해시 알고리즘**(예: SHA-256)을 사용하여 데이터의 무결성을 확인합니다.
	2. **인증 (Authentication)**:
	    - 데이터를 전송하는 장치가 신뢰할 수 있는 장치인지 확인하는 기능을 제공합니다. 이 과정에서 **디지털 서명**과 **인증서**를 사용합니다.
	3. **재전송 방지 (Anti-Replay)**:
	    - 중간에서 패킷을 가로채서 재전송하려는 공격을 막기 위해, 각 패킷에는 고유한 시퀀스 번호가 포함되어 재전송 공격을 차단합니다.
	
	###### IPSec의 작동 방식:
	
	###### IPSec은 두 가지 주요 프로토콜을 사용하여 보안을 제공합니다:
	
	1. **AH (Authentication Header)**:
	    
	    - 데이터의 **무결성**과 **출처 인증**을 제공합니다.
	    - 암호화는 제공하지 않으며, IP 패킷 전체에 대해 인증 정보를 추가합니다.
	    - 패킷이 변경되었거나 위조되었는지 확인할 수 있습니다.
	2. **ESP (Encapsulating Security Payload)**:
	    
	    - 데이터의 **기밀성**(암호화), **무결성**(변조 방지), **인증**을 모두 제공합니다.
	    - 데이터의 암호화와 인증을 수행하며, 가장 많이 사용되는 IPSec 프로토콜입니다.
	
	###### IPSec의 두 가지 운영 모드:
	
	1. **전송 모드 (Transport Mode)**:
	    - IP 패킷의 **데이터(payload)**만 보호하며, IP 헤더는 보호하지 않습니다.
	    - 일반적으로 호스트 간 통신에 사용됩니다.
	2. **터널 모드 (Tunnel Mode)**:
	    - **전체 IP 패킷**(헤더 + 데이터)을 보호하고, 새로운 IP 헤더를 추가합니다.
	    - **VPN**에서 자주 사용되며, 네트워크 간에 안전한 터널을 만들 때 사용됩니다.
	
	###### IPSec의 활용 사례:
	
	- **VPN**(가상 사설망)에서 원격 사용자와 사무실 간의 보안 통신을 위해 자주 사용됩니다.
	- **WAN 연결**에서 데이터의 기밀성, 무결성, 인증을 보장하기 위해 사용됩니다.
	- **데이터센터** 간 통신이나, 보안이 중요한 네트워크에서 안전한 IP 통신을 보장합니다.
	
	###### IPSec의 구성 요소:
	
	1. **SA (Security Association)**: 통신 세션에서 어떤 보안 메커니즘을 사용할지 정의하는 정보(암호화 방식, 키 교환 방식 등)를 포함하는 논리적 연결.
	2. **IKE (Internet Key Exchange)**: 보안 협상과 키 교환을 관리하는 프로토콜로, 안전하게 암호화 키를 교환하는 방법을 제공합니다.
	
	IPSec은 네트워크 계층에서 보안을 제공하기 때문에, 응용 프로그램 수정 없이 전체 통신을 보호할 수 있다는 장점이 있습니다.







#### 6. 다음은 Python에 대한 문제이다. 아래 코드를 읽고 알맞는 출력 값을 작성하시오.

```python
def fnCalculation(x,y):
    result = 0;
    
    for i in range(len(x)):
     temp = x[i:i+len(y)] 
     if temp == y:
       result += 1;
    return result

a = "abdcabcabca"
p1 = "ab";
p2 = "ca";
out = f"ab{fnCalculation(a,p1)}ca{fnCalculation(a,p2)}"
print(out)
```


- 정답 및 해설
  정답 : `ab3ca2`
  해설 :
	이 Python 코드에서 `fnCalculation` 함수는 문자열 `x` 내에서 특정 문자열 `y`가 얼마나 자주 나타나는지 계산하는 역할을 합니다. 코드를 단계별로 분석하고 결과값을 설명하겠습니다.

	### 코드 분석:
	
	#### 1. `fnCalculation` 함수:
	```python
	def fnCalculation(x, y):
	    result = 0
	
	    for i in range(len(x)):
	        temp = x[i:i+len(y)] 
	        if temp == y:
	            result += 1
	    return result
	```
	- **입력 인자**: `x` (검색할 문자열), `y` (찾고자 하는 문자열)
	- **작동 방식**:
	  - `x` 문자열의 길이만큼 반복하면서, `x`의 부분 문자열이 `y`와 같은지 확인합니다.
	  - 확인하는 부분 문자열은 `x[i:i+len(y)]`로, `i`부터 `i+len(y)`까지의 부분 문자열입니다.
	  - 만약 부분 문자열이 `y`와 일치하면, `result` 값을 1 증가시킵니다.
	  - 마지막으로, `result` 값을 반환하여 `y`가 `x`에서 몇 번 등장했는지를 반환합니다.
	
	#### 2. 변수 설정:
	```python
	a = "abdcabcabca"
	p1 = "ab"
	p2 = "ca"
	```
	- `a` = `"abdcabcabca"`: 검색할 문자열.
	- `p1` = `"ab"`: 찾고자 하는 첫 번째 패턴.
	- `p2` = `"ca"`: 찾고자 하는 두 번째 패턴.
	
	#### 3. 함수 호출 및 출력:
	```python
	out = f"ab{fnCalculation(a,p1)}ca{fnCalculation(a,p2)}"
	print(out)
	```
	- `"ab{fnCalculation(a,p1)}ca{fnCalculation(a,p2)}"`는 f-string을 사용하여 `fnCalculation(a, p1)`과 `fnCalculation(a, p2)`의 결과값을 문자열로 삽입합니다.
	- `fnCalculation(a, p1)`과 `fnCalculation(a, p2)`는 각각 `a`에서 `"ab"`와 `"ca"`의 출현 빈도를 계산합니다.
	
	### 과정:
	1. **`fnCalculation(a, p1)`** (`fnCalculation("abdcabcabca", "ab")`):
	   - `a` 문자열에서 `"ab"`가 몇 번 나오는지 확인:
	     - 첫 번째로 `"ab"`는 `a[0:2]`에서 등장.
	     - 두 번째로 `"ab"`는 `a[5:7]`에서 등장.
	     - 세 번째로 `"ab"`는 `a[7:9]`에서 등장.
	     - 결과적으로 `"ab"`는 3번 등장하므로, `fnCalculation(a, p1)`의 결과는 `3`.
	
	2. **`fnCalculation(a, p2)`** (`fnCalculation("abdcabcabca", "ca")`):
	   - `a` 문자열에서 `"ca"`가 몇 번 나오는지 확인:
	     - 첫 번째로 `"ca"`는 `a[4:6]`에서 등장.
	     - 두 번째로 `"ca"`는 `a[9:11]`에서 등장.
	     - 결과적으로 `"ca"`는 2번 등장하므로, `fnCalculation(a, p2)`의 결과는 `2`.
	
	### 최종 출력:
	```python
	out = f"ab{3}ca{2}"
	print(out)
	```
	- 최종 출력은 `"ab3ca2"`가 됩니다.
	
	### 결과:
	```text
	ab3ca2
	```

- 대칭키 알고리즘으로 1997년 NIST(미국 국립기술표준원)에서 DES를 대체하기 위해 생성되었다.

  - 해설 : **AES(Advanced Encryption Standard)** 에 대한 내용을 다루고 있습니다. AES는 1997년 미국 국립기술표준원(NIST)이 DES(Data Encryption Standard)를 대체하기 위해 개발한 **대칭키 암호화 알고리즘**입니다. 이 알고리즘은 **128비트 블록 크기**를 사용하며, **128비트, 192비트, 256비트**의 가변적인 키 크기를 지원합니다. DES보다 더 안전하고 빠르며, 현재 전 세계적으로 가장 많이 사용되는 대칭키 암호화 알고리즘입니다.






#### 8. 패킷 교환 방식 중에 연결형과 비연결형에 해당하는 방식을 작성하시오.

1. 연결형 교환 방식
2. 비연결형 교환 방식

- 정답 및 해설 :
	- 정답 : 가상회선 방식 / 데이터그램 방식
	- 해설 : 
	  ### 문제에서 주어진 설명:

		실행 순서가 밀접한 관계를 가지며, **한 기능의 출력이 다음 기능의 입력이 되는 형태**라고 설명되어 있습니다. 이 설명은 **순차적 응집도(Sequential Cohesion)** 에 해당합니다.
		
		
		### 각 보기별 해설:
		
		1. **ㄱ. 기능적 응집도(Functional Cohesion)**:
		   - **설명**: 모듈 내의 모든 기능이 단일한 목적을 위해 협력하는 경우. 즉, 모듈이 하나의 명확한 기능만을 수행하는 경우.
		   - **특징**: 가장 높은 수준의 응집도이며, 모듈이 명확한 책임을 가짐.
		   - **예**: 파일을 읽어 데이터를 처리하는 기능을 가진 모듈.
		
		2. **ㄴ. 우연적 응집도(Coincidental Cohesion)**:
		   - **설명**: 모듈 내의 기능들이 서로 관련성이 거의 없는 기능들로 구성된 경우.
		   - **특징**: 가장 낮은 응집도로, 모듈의 내부 기능들이 무작위로 묶여 있는 상태.
		   - **예**: 모듈 내에 파일을 읽고, 데이터를 변환하며, 로그를 기록하는 전혀 관련 없는 기능들이 혼합된 경우.
		
		3. **ㄷ. 통신적 응집도(Communicational Cohesion)**:
		   - **설명**: 모듈 내의 기능들이 동일한 데이터나 자원에 대해 작업하는 경우.
		   - **특징**: 모듈 내의 여러 기능들이 같은 데이터 구조나 변수를 처리함.
		   - **예**: 같은 데이터베이스 테이블에 접근하는 여러 함수들이 모듈 내에 존재하는 경우.
		
		4. **ㄹ. 절차적 응집도(Procedural Cohesion)**:
		   - **설명**: 모듈 내의 기능들이 특정 순서대로 실행되지만, 반드시 하나의 특정 데이터나 자원을 처리하지는 않는 경우.
		   - **특징**: 절차적인 흐름에 따라 작업이 이루어지지만, 그 흐름이 데이터와 강하게 연관되어 있지 않음.
		   - **예**: 파일을 열고, 다른 파일로 복사하는 기능들이 절차적으로 연결된 경우.
		
		5. **ㅁ. 시간적 응집도(Temporal Cohesion)**:
		   - **설명**: 모듈 내의 기능들이 **같은 시점**이나 **같은 시간대**에 실행되도록 묶여 있는 경우.
		   - **특징**: 모듈 내의 기능들이 시기적으로 관련이 있을 때 묶여 있음.
		   - **예**: 시스템 시작 시 초기화하는 여러 작업들이 하나의 모듈로 묶여 있는 경우.
		
		6. **ㅂ. 순차적 응집도(Sequential Cohesion)**:
		   - **설명**: 한 기능의 출력이 다음 기능의 입력으로 사용되는 경우, 모듈 내에서 기능들이 **순차적으로 연결**되어 있는 응집도.
		   - **특징**: 출력이 바로 다음 작업의 입력이 되어야 하는 연관성이 있음.
		   - **예**: 데이터 처리 과정에서, 데이터를 읽어 들이고, 가공한 후, 결과를 출력하는 순차적인 작업들이 모듈 내에 있는 경우.
		
		7. **ㅅ. 논리적 응집도(Logical Cohesion)**:
		   - **설명**: 모듈 내의 기능들이 논리적으로 관련이 있는 경우. 비슷한 종류의 작업을 수행하지만 서로 다른 조건에 따라 실행되는 기능들로 구성됨.
		   - **특징**: 기능들이 논리적으로 관련되어 있으나, 특정 조건에 따라 다르게 동작.
		   - **예**: 입력 처리 모듈이 마우스, 키보드, 터치스크린 등의 입력을 처리하는 경우.
		
		---
		
		### 해설:
		- 문제의 설명에서 **한 기능의 출력이 다음 기능의 입력이 되는 형태**는 **순차적 응집도(Sequential Cohesion)**를 의미합니다. 이는 한 모듈 내에서 순차적으로 실행되는 기능들 사이에 밀접한 관계가 있는 경우로, 전 단계의 결과가 다음 단계의 입력으로 사용되는 경우를 뜻합니다.

#### 10. 아래는 디자인 패턴에 관한 설명이다. 아래 설명을 읽고 보기에서 알맞는 용어를 작성하시오.

- 컬렉션 객체의 내부 구조를 노출하지 않고 순차적으로 접근할 수 있게 하는 패턴이다.   
- 이 패턴은 객체의 내부 표현 방식에 독립적으로 요소에 접근할 수 있도록 해준다  
- 반복 프로세스를 캡슐화하여 클라이언트 코드에서는 컬렉션의 구체적인 구현에 종속되지 않도록 한다.

**보기**

| 생성패턴             | 구조패턴      | 행위패턴     |
| ---------------- | --------- | -------- |
| Singleton        | Adapter   | Iterator |
| Factory Method   | Bridge    | Visitor  |
| Abstract Factory | Composite | Observer |


- 정답 및 해설 :
  - 정답 : **Iterator 패턴**
  - 해설 :
	
	### 문제 설명:
	
	주어진 설명은 **Iterator(반복자) 패턴**에 대한 내용입니다. **Iterator 패턴**은 **컬렉션 객체의 내부 구조를 노출하지 않고** 순차적으로 그 안에 들어있는 요소에 접근할 수 있도록 하는 디자인 패턴입니다. 이 패턴을 사용하면 컬렉션의 구체적인 구현과는 독립적으로, 일관된 방식으로 컬렉션의 요소를 반복(iterate)할 수 있습니다.
	
	---
	
	**각 보기별 해설:**
	
	#### 1. **생성 패턴(Creational Patterns)**:
	- **목적**: 객체를 효율적으로 생성하는 방법을 제공하며, 객체 생성과 관련된 복잡성을 줄이는 패턴들입니다.
	  
	  - **Singleton 패턴**:
	    - **설명**: 클래스의 인스턴스를 오직 **하나만** 생성하고, 이 인스턴스에 대한 전역적인 접근을 제공하는 패턴.
	    - **예**: 설정 관리 클래스에서 인스턴스가 하나만 존재해야 할 때 사용.
	    
	  - **Factory Method 패턴**:
	    - **설명**: 객체 생성 코드를 서브클래스에서 정의하여, 상위 클래스에서 구체적인 객체 생성 방식을 결정하지 않도록 하는 패턴.
	    - **예**: 다양한 형태의 객체를 생성하는 인터페이스가 있고, 실제 객체 생성은 서브클래스에서 결정.
	    
	  - **Abstract Factory 패턴**:
	    - **설명**: 관련 객체들의 집합을 생성할 수 있는 **인터페이스**를 제공하며, 구체적인 클래스를 지정하지 않고도 서로 연관된 객체들을 생성하는 패턴.
	    - **예**: GUI 컴포넌트 라이브러리에서 서로 관련된 버튼, 체크박스 등을 패밀리로 묶어 생성.
	
	#### 2. **구조 패턴(Structural Patterns)**:
	- **목적**: 클래스와 객체들을 효율적으로 결합하여 더 큰 구조를 형성할 때 사용하는 패턴입니다. 주로 객체 간의 관계를 정의합니다.
	
	  - **Adapter 패턴**:
	    - **설명**: 클래스의 인터페이스를 클라이언트가 기대하는 다른 인터페이스로 변환하여 호환되지 않는 인터페이스를 가진 클래스를 사용할 수 있게 하는 패턴.
	    - **예**: 서로 다른 전압을 맞추기 위해 사용하는 어댑터처럼, 클라이언트와 호환되지 않는 인터페이스를 맞춰줍니다.
	    
	  - **Bridge 패턴**:
	    - **설명**: 구현부에서 추상층을 분리하여 독립적으로 변경할 수 있도록 하는 패턴.
	    - **예**: 운영체제에 따라 서로 다른 그래픽 API를 사용하는 애플리케이션에서, 추상화된 인터페이스를 통해 API와 독립적으로 기능을 확장할 수 있음.
	    
	  - **Composite 패턴**:
	    - **설명**: 객체들을 트리 구조로 구성하여 개별 객체와 복합 객체를 동일하게 다루도록 하는 패턴.
	    - **예**: 그래픽 인터페이스에서 하나의 요소와 여러 요소가 결합된 복합 요소를 동일하게 처리하는 구조.
	
	#### 3. **행위 패턴(Behavioral Patterns)**:
	- **목적**: 객체들 간의 상호작용과 책임 분담을 정의하는 패턴들입니다. 객체들의 통신 방법을 정의하고, 프로그램 내의 객체들이 서로 어떻게 협력하는지를 명확하게 설명합니다.
	
	  - **Iterator 패턴** (정답):
	    - **설명**: **컬렉션의 내부 구조를 노출하지 않고**, 순차적으로 그 안에 들어있는 요소에 접근할 수 있게 하는 패턴.
	    - **예**: 리스트, 트리 등의 자료 구조에서 내부 구현에 의존하지 않고 요소를 반복하는 방법을 제공.
	
	  - **Visitor 패턴**:
	    - **설명**: 객체 구조의 각 요소에 대해 연산을 수행할 수 있게 하는 패턴. 구조에 새로운 기능을 추가할 때 기존 구조를 변경하지 않고도 연산을 추가할 수 있음.
	    - **예**: 문서의 각 페이지를 방문하며 텍스트나 이미지를 처리하는 경우.
	
	  - **Observer 패턴**:
	    - **설명**: **한 객체의 상태 변화에 따라 다른 객체들이 자동으로 알림을 받고 업데이트**할 수 있는 패턴. 주로 이벤트 핸들링이나 데이터 변경 알림에 사용됨.
	    - **예**: GUI 프로그램에서 버튼을 클릭하면 관련된 리스너가 해당 이벤트를 처리하는 방식.
	
	---
	
	### 해설:
	- **Iterator 패턴**은 컬렉션 내부의 세부 구현을 클라이언트 코드에 드러내지 않고, 일관된 방식으로 순차적으로 요소에 접근할 수 있도록 해줍니다. 이 패턴은 여러 자료구조에서 동일한 인터페이스로 데이터를 탐색할 수 있게 해주며, 코드의 유연성을 높입니다.

	**SRT (Shortest Remaining Time)** 스케줄링은 **선점형 스케줄링 기법**의 하나로, 새로운 프로세스가 도착할 때 현재 실행 중인 프로세스와 비교하여 남은 실행 시간이 더 짧은 프로세스를 우선으로 실행합니다. 즉, 실행 중인 프로세스가 있더라도 남은 시간이 더 짧은 프로세스가 도착하면 현재 프로세스를 중단하고 새로운 프로세스를 실행합니다.
	
	---
	
	### 주어진 프로세스 정보:
	
	![[{0631F423-8901-4475-B996-484F168CB3C5}.png]]
	
	---
	
	### SRT 스케줄링에 따른 실행 순서:
	
	1. **0초**: 프로세스 A 도착 → A 실행 (남은 시간: 8)
	2. **1초**: 프로세스 B 도착 → B의 남은 시간이 더 짧으므로 A 중단, B 실행 (A의 남은 시간: 7, B 실행 시작)
	3. **2초**: 프로세스 C 도착 → B가 계속 실행 (C의 남은 시간: 9, B의 남은 시간: 3)
	4. **3초**: 프로세스 D 도착 → B가 계속 실행 (D의 남은 시간: 5, B의 남은 시간: 2)
	5. **5초**: B 종료 → D 실행 (D의 남은 시간: 5)
	6. **10초**: D 종료 → A 실행 (A의 남은 시간: 7)
	7. **17초**: A 종료 → C 실행 (C의 남은 시간: 9)
	8. **26초**: C 종료
	
	---
	
	### 각 프로세스의 종료 시간:
	
	- **A**: 17초에 종료
	- **B**: 5초에 종료
	- **C**: 26초에 종료
	- **D**: 10초에 종료
	
	### 각 프로세스의 대기 시간 계산:
	
	대기 시간 = 종료 시간 - 도착 시간 - 서비스 시간
	
	- **A**: 17 - 0 - 8 = **9**
	- **B**: 5 - 1 - 4 = **0**
	- **C**: 26 - 2 - 9 = **15**
	- **D**: 10 - 3 - 5 = **2**
	
	---
	
	### 평균 대기 시간 계산:
	
	\[\text{평균 대기 시간} = \frac{9 + 0 + 15 + 2}{4} = \frac{26}{4} = 6.5\]
	
	### 최종 답:
	
	**평균 대기 시간은 6.5초**입니다.
	
	---
	
	### 해설:
	- **SRT 스케줄링**은 선점형 스케줄링 방식으로, 새로운 프로세스가 도착할 때마다 현재 실행 중인 프로세스와 비교하여 남은 실행 시간이 더 짧은 프로세스를 우선 실행합니다. 이로 인해 짧은 작업이 먼저 처리되며, 실행 도중 더 짧은 작업이 들어오면 현재 작업이 중단됩니다.
	- 주어진 예시에서는 프로세스 B가 도착한 후 A가 중단되고, B가 완료된 후 다시 D, A, C 순으로 실행되었습니다.

#### 16. 아래는 소프트웨어 설계에 대한 내용이다. 내용을 읽고 괄호안에 알맞는 답을 작성하시오.

- 어떤 모듈이 다른 모듈 내부의 논리적인 흐름을 제어하기 위해, 제어를 통신하거나 제어 요소를 전달하는 결합도이다.  
- 한 모듈이 다른 모듈의 상세한 처리 절차를 알고 있어 이를 통제하는 경우나 처리 기능이 두 모듈에 분리되어 설계된 경우에 발생한다.

(              ) Coupling



- 정답 및 해설
  - 정답 : **Control Coupling** (제어 결합)
  - 해설 :
	**Control Coupling (제어 결합)** 은 소프트웨어 설계에서 **한 모듈이 다른 모듈의 내부적인 논리 흐름을 제어**하는 경우에 발생하는 결합을 의미합니다. 이는 한 모듈이 다른 모듈의 처리 흐름을 제어하거나, **제어 요소(플래그, 조건문)** 를 전달하여 제어권을 넘기는 방식에서 발생합니다.
	
	제어 결합은 **모듈 간 결합도** 중에서 바람직하지 않은 결합도로 간주됩니다. 이는 한 모듈이 다른 모듈의 내부 동작을 너무 많이 알고 있어야 하며, 모듈 간의 독립성이 낮아지기 때문입니다.
	
	### 예시:
	- **Control Coupling**이 발생하는 예는 두 모듈 간에 하나의 모듈이 다른 모듈에게 **제어 흐름에 영향을 미치는 정보**를 전달하는 경우입니다. 예를 들어, 한 모듈이 다른 모듈에 **플래그(flag)** 를 전달하여 그 모듈의 동작 방식을 제어하는 경우, 이 두 모듈 사이에 제어 결합이 발생했다고 볼 수 있습니다.
	
	### 결합도(Coupling)란?
	모듈 간의 **결합도(Coupling)** 는 서로 다른 모듈 간의 상호 의존성을 나타냅니다. 결합도가 낮을수록 모듈 간의 독립성이 높아져 유지보수가 용이하고, 시스템의 확장성도 높아집니다. 반면 결합도가 높을수록 모듈 간의 의존성이 커져 변화에 대한 유연성이 떨어집니다.
	
	### 결합도의 종류 (낮은 결합도 → 높은 결합도):
	1. **자료 결합(Data Coupling)**: 모듈 간에 단순한 데이터만 주고받는 경우.
	2. **스탬프 결합(Stamp Coupling)**: 데이터 구조나 객체를 전달하는 경우.
	3. **제어 결합(Control Coupling)**: 한 모듈이 다른 모듈의 내부 논리 흐름을 제어하는 경우.
	4. **외부 결합(External Coupling)**: 모듈이 외부의 공통 자원(파일, 디바이스 등)을 공유하는 경우.
	5. **공유 결합(Common Coupling)**: 여러 모듈이 전역 변수나 공통 데이터를 공유하는 경우.
	6. **내용 결합(Content Coupling)**: 한 모듈이 다른 모듈의 내부 구현에 직접 접근하여 사용하는 경우.
	
	### 결론:
	문제에서 설명한 결합도는 **제어 결합(Control Coupling)** 에 해당합니다. 이는 한 모듈이 다른 모듈의 논리 흐름을 직접적으로 제어하려고 할 때 발생하며, 결합도 중에서는 **높은 결합도** 에 속해, 바람직하지 않은 설계 방식으로 여겨집니다.

#### 18. 다음은 C언어에 대한 문제이다. 아래 코드를 확인하여 알맞는 출력 값을 작성하시오.

```C
#include <stdio.h>
void swap(int a, int b) {
    int t = a;
    a = b;
    b = t;
}

int main() {
    int a = 11;
    int b = 19;
    
    swap(a, b);
    
    switch(a) {
        case 1:
            b += 1;
        case 11:
            b += 2;
        default:
            b += 3;
        break;
    }
    printf("%d", a-b);
}
```


- 정답 및 해설
  - 정답 : -**13**
  - 해설 :
	### 문제 분석:
	
	주어진 C 프로그램은 다음의 두 가지 주요 개념을 포함합니다:
	1. **`swap` 함수**: 두 변수 `a`와 `b`의 값을 교환하려고 하지만, C에서는 값에 의한 호출(`call by value`)을 사용하므로 원본 변수에는 영향을 미치지 않습니다.
	2. **`switch` 문**: 변수 `a`의 값을 기반으로 `b`의 값을 변경하는 논리 흐름입니다.
	
	### 코드 흐름 분석:
	
	#### 1. **`swap` 함수**:
	```c
	void swap(int a, int b) {
	    int t = a;
	    a = b;
	    b = t;
	}
	```
	- 이 함수는 `a`와 `b`의 값을 교환하려고 하지만, 함수는 **값에 의한 호출**(`call by value`)을 사용합니다. 따라서 **`main` 함수 내의 변수 `a`와 `b`는 변경되지 않습니다**. 함수 내부에서만 교환이 이루어지며, 호출한 쪽에서는 원래 변수의 값에 영향을 미치지 않습니다.
	
	#### 2. **`main` 함수**:
	```c
	int a = 11;
	int b = 19;
	
	swap(a, b);
	```
	- 변수 `a`는 **11**, 변수 `b`는 **19**로 초기화됩니다.
	- **`swap(a, b)`**는 **값에 의한 호출**이므로 `a`와 `b`는 교환되지 않고, 여전히 **a = 11**, **b = 19**입니다.
	
	#### 3. **`switch` 문**:
	```c
	switch(a) {
	    case 1:
	        b += 1;
	    case 11:
	        b += 2;
	    default:
	        b += 3;
	    break;
	}
	```
	- **`a = 11`**이므로 `switch(a)`에서 **`case 11`**이 실행됩니다.
	- `b`에 **2**가 더해져 **b = 19 + 2 = 21**이 됩니다.
	- **`case 11`** 아래에 `break`가 없으므로 **`default`** 문도 실행됩니다.
	- `b`에 **3**이 더해져 **b = 21 + 3 = 24**가 됩니다.
	
	#### 4. **`printf` 함수**:
	```c
	printf("%d", a - b);
	```
	- **a = 11**, **b = 24**이므로 `a - b = 11 - 24 = -13`이 됩니다.
	
	### 최종 출력값:
	```c
	-13
	```
	
	### 해설:
	- **`swap` 함수**는 값에 의한 호출로 인해 변수 `a`와 `b`를 교환하지 않습니다. 즉, 원본 변수의 값은 변경되지 않습니다.
	- **`switch` 문**에서 변수 `a`가 11이므로 `case 11`이 실행되고, 그 이후에 `default`가 실행됩니다. 이로 인해 변수 `b`의 값이 최종적으로 **24**가 됩니다.
	- 최종적으로 **`printf`**는 `a - b = 11 - 24`를 계산하여 **`-13`**을 출력합니다.
	






#### 19. 다음은 C언어의 구조체에 대한 문제이다. 아래 코드를 확인하여 알맞는 출력 값을 작성하시오.

```C
#include <stdio.h>

struct node {
    int n1;
    struct node *n2;
};

int main() {
    struct node a = {10, NULL};
    struct node b = {20, NULL};
    struct node c = {30, NULL};
    struct node *head = &a;

	a.n2 = &b;
    b.n2 = &c;

    printf("%d\n", head->n2->n1);

    return 0;
}
```


- 정답 및 해설
  - 정답 : **`20`**
  - 해설 :
	### 문제 분석:
	
	이 C 언어 프로그램은 구조체와 포인터를 사용하여 연결 리스트를 구성하고 있습니다. 주어진 코드를 따라 구조체의 연결을 추적하고, 최종적으로 출력되는 값을 계산해보겠습니다.
	
	### 코드 분석:
	
	#### 1. **구조체 정의**:
	```c
	struct node {
	    int n1;
	    struct node *n2;
	};
	```
	- `struct node`는 두 개의 멤버를 갖는 구조체입니다:
	  - `n1`: 정수형 변수
	  - `n2`: 같은 구조체를 가리키는 포인터로, 다음 `node`를 가리키는 역할을 합니다.
	
	#### 2. **구조체 변수 초기화**:
	```c
	struct node a = {10, NULL};
	struct node b = {20, NULL};
	struct node c = {30, NULL};
	struct node *head = &a;
	```
	- `a`, `b`, `c`는 각각 `node` 구조체의 인스턴스로 초기화됩니다.
	  - `a.n1 = 10`, `a.n2 = NULL`
	  - `b.n1 = 20`, `b.n2 = NULL`
	  - `c.n1 = 30`, `c.n2 = NULL`
	- `head`는 `struct node` 포인터로 `a`의 주소를 가리키고 있습니다 (`head = &a`).
	
	#### 3. **구조체 포인터 연결**:
	```c
	a.n2 = &b;
	b.n2 = &c;
	```
	- `a.n2`가 `b`의 주소를 가리키도록 설정됩니다. 즉, `a`는 이제 `b`를 가리키는 연결 관계를 갖습니다.
	- `b.n2`가 `c`의 주소를 가리키도록 설정됩니다. 즉, `b`는 이제 `c`를 가리킵니다.
	
	#### 4. **현재 연결 관계**:
	- `head → a (n1 = 10, n2 = &b)`
	- `a → b (n1 = 20, n2 = &c)`
	- `b → c (n1 = 30, n2 = NULL)`
	
	구조체의 연결은 다음과 같이 이루어집니다:
	```
	head → a → b → c
	```
	
	#### 5. **`printf` 문**:
	```c
	printf("%d\n", head->n2->n1);
	```
	- `head`는 `a`를 가리키고 있으므로 `head->n2`는 `a.n2`와 같습니다.
	- `a.n2`는 `b`를 가리키고 있으므로 `head->n2`는 `b`를 가리키게 됩니다.
	- `b.n1`은 20이므로 `head->n2->n1`은 `20`입니다.
	
	### 최종 출력:
	```c
	20
	```
	
	### 해설:
	- 이 프로그램은 `struct node`를 사용하여 세 개의 노드(`a`, `b`, `c`)를 연결하는 간단한 연결 리스트를 구현하고 있습니다.
	- `a`의 `n2` 포인터는 `b`를 가리키고, `b`의 `n2` 포인터는 `c`를 가리킵니다.
	- `head` 포인터는 `a`를 가리키며, `head->n2->n1`은 `b`의 `n1` 값을 참조합니다. 따라서 출력은 **`20`** 이 됩니다.
