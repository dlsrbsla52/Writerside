#### 1. 다음은 Java 코드이다. 올바른 출력 결과를 작성하시오.
```java
public class main{

    public static void main(String[] args) {
        A b = new B();
        b.paint();
        b.draw();
    }
}

class A {
    public void paint() {
        System.out.print("A");
        draw();
    }

    public void draw() {
        System.out.print("B");
        draw();
    }

}

class B extends A {
    public void paint() {
        super.draw();
        System.out.print("C");
        this.draw();
    }

    public void draw() {
        System.out.print("D");
    }
}
```



- 정답 및 해설
  - 정답 : `BDCDD`
  - 해설 :
	### 코드 흐름 분석:
	
	1. **객체 생성**:
	   ```java
	   A b = new B();
	   ```
	   - `b`는 **`A` 타입**이지만, **`B` 클래스**의 객체입니다.
	
	2. **첫 번째 메서드 호출 (`b.paint()`)**:
	   - `b.paint()`는 **`B` 클래스의 `paint()`** 가 호출됩니다. **`B` 클래스에서 `A` 클래스의 `paint()`** 를 오버라이딩했기 때문입니다.
	   
	   ```java
	   public void paint() {
	       super.draw();
	       System.out.print("C");
	       this.draw();
	   }
	   ```
	
	   - **`super.draw()`**: `super`는 부모 클래스의 메서드를 호출합니다. 즉, **`A` 클래스의 `draw()`** 가 호출됩니다.
	     - `A` 클래스의 `draw()`는 다음과 같습니다:
	       ```java
	       public void draw() {
	           System.out.print("B");
	       }
	       ```
	     - 따라서, **`B`**가 출력됩니다.
	
	   - **`System.out.print("C")`**: `C`가 출력됩니다.
	
	   - **`this.draw()`**: 여기서 `this`는 **`B` 클래스의 인스턴스**이므로 **`B` 클래스의 `draw()`** 가 호출됩니다.
	     - **`D`**가 출력됩니다.
	
	   - 따라서, 첫 번째 메서드 호출(`b.paint()`)에서 출력되는 값은 **`BDC`** 입니다.
	
	3. **두 번째 메서드 호출 (`b.draw()`)**:
	   - `b.draw()`는 **`B` 클래스의 `draw()`**가 호출됩니다.
	   - 따라서, **`D`** 가 출력됩니다.
	
	### 최종 출력:
	
	```java
	BDCDD
	```
	
	---
	
	### 해설:
	
	1. **첫 번째 메서드 호출**: `b.paint()`는 **`B` 클래스**의 `paint()` 메서드를 호출합니다. 이 메서드는 `super.draw()`를 호출하여 **`A` 클래스의 `draw()`** 메서드를 실행하고, `C`를 출력한 후, **`B` 클래스의 `draw()`** 를 다시 실행합니다.
	2. **두 번째 메서드 호출**: `b.draw()`는 **`B` 클래스의 `draw()`**를 호출하여 `D`를 출력합니다.
	
	최종적으로 **`BDCDD`** 가 출력됩니다.

	5. **Facebook, Twitter 등 소셜 미디어 플랫폼에서 널리 사용됨** → OAuth는 많은 소셜 미디어 플랫폼에서 사용되며, 사용자 데이터에 대한 액세스를 타사 애플리케이션에 부여하는 데 사용됩니다.

#### 3. 리눅스(Linux)에서 사용자에게 읽기/쓰기/실행 권한을 부여하고, 그룹에게는 읽기/실행을 부여하고, 그 이외에는 실행 권한을 test.txt 파일에 부여하는 위한 명령어는 다음과 같다. 빈칸에 들어갈 답을 작성하시오. (8진법 사용)

	### 문제 분석:

	- **쓰기 (w)**: 2

```C
#include <stdio.h>
```

	### 문제 분석:
	
	주어진 C 코드에서의 목표는 **완전수(perfect number)** 를 찾아 합을 구하는 것입니다.
	
	#### 완전수란?
	- **완전수**는 자신을 제외한 약수의 합이 자신과 같은 수를 말합니다.
	  - 예: 6은 약수가 1, 2, 3이고, 이들의 합이 6이므로 완전수입니다.
	  - 또 다른 예로 28도 완전수입니다. 약수가 1, 2, 4, 7, 14이고 이들의 합이 28입니다.
	
	### 코드 설명:
	
	1. **`test` 함수**:
	   ```c
	   int test(int n) {
	       int i, sum = 0;
	       
	       for (i = 1; i <= n / 2; i++) {
	           if (n % i == 0)
	               sum += i;
	       }
	
	       if (n == sum) return 1;
	
	       return 0;
	   }
	   ```
	   - 이 함수는 매개변수 `n`이 **완전수인지 확인**하는 함수입니다.
	   - `n`의 약수를 구해 그 합이 `n`과 같은지 검사합니다.
	   - 만약 `n`이 완전수이면 1을 반환하고, 그렇지 않으면 0을 반환합니다.
	
	2. **`main` 함수**:
	   ```c
	   int main(){
	       int i, sum = 0;
	       for (i = 2; i <= 100; i++){ 
	           if (test(i))
	               sum += i;
	       }
	       printf("%d ", sum); 
	       return 0;
	   }
	   ```
	   - `main` 함수는 **2부터 100까지의 수 중 완전수를 찾아 그 합을 구하는 역할**을 합니다.
	   - 2부터 100까지 숫자 중에서 **완전수인 숫자를 찾으면 `sum`에 더합니다**.
	   - 최종적으로 **완전수의 합**을 출력합니다.
	
	### 완전수 찾기:
	
	1. **6**:
	   - 약수: 1, 2, 3
	   - 1 + 2 + 3 = 6
	   - 완전수입니다.
	
	2. **28**:
	   - 약수: 1, 2, 4, 7, 14
	   - 1 + 2 + 4 + 7 + 14 = 28
	   - 완전수입니다.
	
	### 2부터 100까지의 완전수:
	- **6**과 **28**만 완전수입니다.
	
	### 최종 합계:
	- 6 + 28 = **34**
	
	---
	
	### 최종 출력값:
	
	```c
	34
	```
	
	---
	
	### 해설:
	
	- 이 프로그램은 2부터 100까지의 수 중에서 **완전수**를 찾는 코드입니다. **완전수**는 자신을 제외한 약수들의 합이 자기 자신과 같은 수를 의미합니다.
	- 2부터 100 사이에 있는 완전수는 **6**과 **28**이며, 이들의 합은 **34**입니다.

	   ```c
	   int main() {
	   ```

	   ```c
	   printf("%d\n", *d1.numPtr);
	   printf("%d\n", *d2->numPtr);
	   ```

	   - `*d2->numPtr`: `d2`의 `numPtr` 포인터가 가리키는 `num`의 값인 10을 출력합니다.

	---
	
	### 코드 분석:
	
	1. **`f(int n)` 함수**:

	### 팩토리얼 계산 과정 (`f(7)`):
	
	```
	f(7) = 7 * f(6)
	     = 7 * (6 * f(5))
	     = 7 * (6 * (5 * f(4)))
	     = 7 * (6 * (5 * (4 * f(3))))
	     = 7 * (6 * (5 * (4 * (3 * f(2)))))
	     = 7 * (6 * (5 * (4 * (3 * (2 * f(1))))))
	     = 7 * (6 * (5 * (4 * (3 * (2 * 1)))))
	     = 7 * 6 * 5 * 4 * 3 * 2 * 1

	```


#### 12. IP 패킷에서 외부의 공인 IP주소와 포트 주소에 해당하는 내부 IP주소를 재기록하여 라우터를 통해 네트워크 트래픽을 주고받는 기술은 무엇인가?

- 정답 및 해설 :

	### 정답: **NAT (Network Address Translation)**
	
	---
	
	### 해설:
	
	**NAT (Network Address Translation)** 는 **내부 네트워크의 사설 IP 주소** 를 **외부에서 접근 가능한 공인 IP 주소**로 변환하는 기술입니다. 이 기술은 라우터나 방화벽에서 주로 사용되며, **내부 네트워크와 외부 네트워크 간의 트래픽을 주고받을 때, 내부 IP 주소를 숨기고 공인 IP 주소로 변환**하는 역할을 합니다.
	
	### NAT의 동작 방식:
	
	1. **내부 네트워크**에 있는 장치들은 사설 IP 주소를 사용합니다. 이 사설 IP 주소는 인터넷에서 직접 사용될 수 없습니다.
	2. **NAT 기술**을 사용하면, 내부 장치가 외부로 트래픽을 보낼 때 **사설 IP 주소를 공인 IP 주소로 변환**하여 외부 네트워크와 통신할 수 있게 해줍니다.
	3. 반대로 외부에서 들어오는 패킷은 **공인 IP 주소**로 도착하게 되며, NAT 장치는 이를 **내부 IP 주소로 변환**하여 내부 네트워크로 전달합니다.
	4. 또한, NAT는 **포트 번호**를 사용해 여러 내부 장치들이 동일한 공인 IP 주소로 외부와 통신할 수 있도록 해줍니다.
	
	### NAT의 주요 역할:
	
	- **IP 주소 절약**: 사설 IP 주소를 사용하여 여러 장치가 하나의 공인 IP 주소를 공유하게 함으로써, 공인 IP 주소의 부족 문제를 해결합니다.
	- **보안 강화**: NAT를 통해 내부 네트워크의 IP 주소를 숨길 수 있어, 외부에서 내부 장치를 직접적으로 식별할 수 없게 합니다.
	
	---
	
	### 결론:
	
	**NAT (Network Address Translation)** 는 내부의 사설 IP 주소를 외부에서 접근 가능한 공인 IP 주소로 변환하여 네트워크 트래픽을 주고받는 기술입니다. 이는 IP 주소 절약과 보안 강화 측면에서 매우 유용한 기술입니다.

```java
        obj.print();
    }

```



- 정답 및 해설
  - 정답 : 7
  - 해설 :
	### 문제 분석:
	
	주어진 코드에서 에러가 발생하는 이유는 **정적 메서드(static method)**와 **인스턴스 변수(instance variable)** 사이의 접근 문제입니다.
	
	---
	
	### 에러가 발생하는 라인:
	
	```java
	public static String get() {
	    return name;
	}
	```
	
	이 코드에서 에러가 발생하는 이유는 **`name`이 인스턴스 변수**인데, 이를 **정적 메서드(static method)**인 `get()`에서 직접 참조하려고 하기 때문입니다.
	
	### 문제의 원인:
	
	- **`name`은 인스턴스 변수**입니다. 즉, 각 인스턴스마다 고유한 값을 가질 수 있는 변수입니다.
	- 하지만 **`get()` 메서드는 정적 메서드**입니다. 정적 메서드는 클래스 단위로 호출되며, 인스턴스 없이 호출되기 때문에 **인스턴스 변수에 접근할 수 없습니다**.
	- 정적 메서드에서는 **인스턴스 변수에 직접 접근할 수 없으며**, 대신 **클래스 변수(static 변수)**에만 접근할 수 있습니다.
	
	### 해결 방법:
	
	1. **정적 메서드 `get()`에서 인스턴스 변수를 사용하려면**, `name`을 **static**으로 선언해야 합니다:
	   ```java
	   private static String name;
	   ```
	
	   그러나, 이렇게 하면 모든 `Person` 인스턴스가 동일한 `name` 값을 공유하게 됩니다.
	
	2. 또는 **`get()` 메서드를 인스턴스 메서드**로 변경하여 해결할 수 있습니다:
	   ```java
	   public String get() {
	       return name;
	   }
	   ```
	
	   이렇게 하면 `get()` 메서드는 각 인스턴스의 `name` 값을 반환할 수 있습니다.
	
	---
	
	### 최종 결론:
	
	- **에러가 발생하는 라인**: `public static String get() { return name; }`
	- 이유는 **정적 메서드가 인스턴스 변수에 접근하려고 했기 때문**입니다.

	---
	
	### 키워드 분석:
	
	1. **입력값과 출력값이 특정 그룹으로 분류되며, 분류된 그룹 내의 값들이 동일하게 취급된다는 특성**:
	   - **Equivalence Partitioning**은 입력값을 특정 **동등 분할 그룹**으로 나누는 기법입니다. 한 그룹 내의 값들은 테스트 시스템에서 동일하게 처리될 것으로 가정합니다.
	
	2. **유사한 입력값들이 시스템을 거치면서 유사한 답변이 나온다는 것을 가정**:
	   - 동일한 그룹 내의 값들은 시스템에서 유사하게 처리된다고 가정합니다. 따라서 각 그룹에서 하나의 값을 대표로 선택해 테스트합니다.
	
	3. **하나의 값은 그 분할 내 모든 값을 대표하는 것으로 간주**:
	   - 그룹 내에서 하나의 테스트 케이스는 해당 그룹의 모든 값을 대표하므로, 모든 입력값을 테스트하지 않고도 효율적으로 테스트를 진행할 수 있습니다.
	
	4. **경계값 분석기법(boundary value analysis)과 함께 테스트 케이스 도출**:
	   - **동등 분할 기법**은 **경계값 분석(boundary value analysis)**과 함께 자주 사용되며, 경계값 분석은 **경계에 위치한 값**들을 중점적으로 테스트하는 기법입니다.
	
	---
	
	### 보기 분석:
	
	1. **ㄱ. Equivalence Partitioning**:
	   - 입력값을 그룹으로 나누어 각 그룹에서 대표 값을 테스트하는 기법으로, 설명에 맞습니다.
	
	2. **ㄴ. Statement Coverage**:
	   - 코드의 각 문장이 최소한 한 번 실행되었는지를 테스트하는 **구문 커버리지** 기법으로, 주어진 설명과 관련이 없습니다.
	
	3. **ㄷ. Boundary Value Analysis**:
	   - 경계값을 중점적으로 테스트하는 기법이므로, **동등 분할 기법과 함께 사용**되지만, 주어진 설명에 해당하지는 않습니다.
	
	4. **ㄹ. Branch Coverage**:
	   - 조건문에서 발생할 수 있는 모든 경로를 테스트하는 기법으로, 설명과 관련이 없습니다.
	
	5. **ㅁ. Error Guessing**:
	   - 경험을 바탕으로 오류가 발생할 가능성이 높은 부분을 추측하여 테스트하는 기법입니다.
	
	6. **ㅂ. Condition Coverage**:
	   - 각 조건이 참 또는 거짓을 모두 테스트했는지를 확인하는 기법입니다.
	
	7. **ㅅ. Cause Effect Graph**:
	   - 입력과 결과 간의 관계를 그래프로 나타내어 테스트하는 기법입니다.
	
	---

	- 주어진 설명은 **Equivalence Partitioning (동등 분할 기법)** 에 대한 설명입니다. 이는 입력값을 그룹으로 나누어 각 그룹에서 대표 값을 테스트함으로써 효율적으로 테스트를 수행하는 기법입니다.

- 거리와 방향으로 길을 찾아가는 Distance Vector 다이나믹 프로토콜이다.
- 최단거리 즉, Hop count가 적은 경로를 택하여 라우팅하는 프로토콜로 Routing Table에 인접 라우터 정보를 저장하여 경로를 결정한다.
- 최대 Hop count는 15로 거리가 짧기 때문에 IGP로 많이 이용하는 프로토콜이다.


- 정답 및 해설
  - 정답 : **RIP (Routing Information Protocol)**
  - 해설 :
	주어진 설명은 다음과 같습니다:
	
	1. **최소 Hop count를 파악하여 라우팅하는 프로토콜이다.**
	   - RIP는 경로를 선택할 때 홉 수(Hop count)를 기준으로 최단 경로를 선택합니다.
	
	2. **거리와 방향으로 길을 찾아가는 Distance Vector 다이나믹 프로토콜이다.**
	   - RIP는 Distance Vector 알고리즘을 사용하여 인접 라우터로부터 거리 정보를 받아 경로를 계산합니다.
	
	3. **최단거리 즉, Hop count가 적은 경로를 택하여 라우팅하는 프로토콜로 Routing Table에 인접 라우터 정보를 저장하여 경로를 결정한다.**
	   - 라우팅 테이블에 인접 라우터의 정보를 저장하고, 홉 수가 가장 적은 경로를 선택합니다.
	
	4. **최대 Hop count는 15로 거리가 짧기 때문에 IGP로 많이 이용하는 프로토콜이다.**
	   - RIP의 최대 홉 수는 15로 제한되어 있으며, 16 홉 이상의 네트워크는 도달 불가능한 것으로 간주됩니다. 이 때문에 소규모 네트워크에서 내부 게이트웨이 프로토콜(IGP)로 많이 사용됩니다.
	
	---
	
	이러한 특징을 모두 만족하는 프로토콜은 **RIP(Routing Information Protocol)** 입니다. RIP는 Distance Vector 기반의 라우팅 프로토콜로, 네트워크 규모가 작은 환경에서 간단하고 효율적인 라우팅을 제공하기 위해 설계되었습니다.





#### 19. 다음은 관계 대수에 대한 내용이다. 보기에 알맞는 기호를 작성하시오.

1. join :   (   1   )
2. project :   (   2   )
3. select :   (   3   )
4. division :   (   4   )

보기

| ㄱ. σ              ㄴ.  π                   ㄷ.⋈                 ㄹ.÷ |
| ----------------------------------------------------------------- |


- 정답 및 해설
  - 정답 :
	1. join :  ( **ㄷ** )
	2. project :  ( **ㄴ** )
	3. select :  ( **ㄱ** )
	4. division :  ( **ㄹ** )
	
  - 해설 :
	1. **join (조인)**:
	   - **기호:** ⋈ (**ㄷ**)
	   - **설명:** 두 개의 관계를 특정 조건에 따라 결합하여 새로운 관계를 생성하는 연산입니다. 조인을 통해 관련된 데이터를 하나의 관계로 묶을 수 있습니다.
	
	2. **project (프로젝션)**:
	   - **기호:** π (**ㄴ**)
	   - **설명:** 관계에서 특정 속성들만 선택하여 새로운 관계를 만드는 연산입니다. 원하는 열(Column)만 추출할 때 사용합니다.
	
	3. **select (셀렉션)**:
	   - **기호:** σ (**ㄱ**)
	   - **설명:** 관계에서 조건을 만족하는 튜플(행)들만 선택하는 연산입니다. WHERE 절과 유사하게 특정 조건에 맞는 데이터를 필터링합니다.
	
	4. **division (디비전)**:
	   - **기호:** ÷ (**ㄹ**)
	   - **설명:** 두 관계 간의 나눗셈을 수행하는 연산으로, 한 관계의 튜플이 다른 관계의 모든 튜플과 연관된 튜플을 찾을 때 사용합니다.
	
	---
	
	**요약:**
	
	- **σ (셀렉션)**: 조건에 맞는 튜플 선택
	- **π (프로젝션)**: 특정 속성만 선택
	- **⋈ (조인)**: 두 관계 결합
	- **÷ (디비전)**: 관계 간 나눗셈









#### 20. 다음은 데이터베이스에 관련된 문제이다. 괄호 안에 알맞는 답을 작성하시오.

- (            ) 무결성은 관계 데이터베이스 관계 모델에서 2개의 관련 있던 관계 변수(테이블) 간의 일관성(데이터 무결성)을 말한다.
- 종종 기본 키 또는 키가 아닌 후보 키와 외래 키의 조합으로 강제 적용된다.
- 외래 키가 선언된 관계 변수의 외래 키를 구성하는 속성(열)의 값은 그 관계 변수의 부모가 되는 관계 변수의 기본 키 값 또는 기본 키가 아닌 후보 키 값으로 존재해야 한다.



- 정답 및 해설
  - 정답 : 참조
  - 해설:
	
	주어진 문제는 관계형 데이터베이스에서 두 개의 관련된 관계 변수(테이블) 간의 일관성을 유지하기 위한 무결성 제약 조건에 대해 묻고 있습니다. 이 무결성은 외래 키와 기본 키 또는 후보 키의 관계를 통해 데이터의 일관성과 정확성을 보장합니다.
	
	### **참조 무결성 (Referential Integrity)**
	
	- **정의:**
	  - 참조 무결성은 **두 테이블 간의 관계에서 외래 키가 부모 테이블의 기본 키 또는 후보 키 값을 반드시 참조하도록 강제하는 무결성 제약 조건**입니다.
	  - 이는 데이터베이스에서 **데이터의 일관성(consistency)**과 **무결성(integrity)**을 유지하기 위해 필수적입니다.
	
	- **특징:**
	  - **외래 키(Foreign Key)**:
	    - 자식 테이블에서 부모 테이블의 기본 키나 후보 키를 참조하는 속성입니다.
	    - 외래 키의 값은 **NULL이거나**, 부모 테이블에 **실제로 존재하는 값**이어야 합니다.
	  - **기본 키(Primary Key)** 또는 **후보 키(Candidate Key)**:
	    - 테이블에서 각 튜플을 **유일하게 식별**할 수 있는 속성 또는 속성의 집합입니다.
	
	- **적용 방법:**
	  - 외래 키 제약을 선언하여 참조 무결성을 강제합니다.
	  - 데이터 삽입, 수정, 삭제 시 참조 무결성 규칙을 위반하지 않도록 데이터베이스 관리 시스템(DBMS)이 자동으로 검사합니다.
	
	- **예시:**
	  - **학생 테이블(Student)**과 **수강 신청 테이블(Enrollment)**이 있을 때, 수강 신청 테이블의 **학생 ID**는 학생 테이블의 **학생 ID**를 외래 키로 참조합니다.
	  - 이때, 수강 신청 테이블에 존재하는 학생 ID는 반드시 학생 테이블에 존재해야 하며, 그렇지 않으면 참조 무결성이 깨집니다.
	
	### **요약:**
	
	- **참조 무결성**은 관계형 데이터베이스에서 **두 테이블 간의 데이터 일관성을 유지**하기 위한 중요한 개념입니다.
	- 외래 키와 기본 키 또는 후보 키의 관계를 통해 데이터의 무결성을 보장합니다.
	- 따라서 빈칸에 알맞은 답은 **"참조"**입니다.
	
	---
	
	**답변 요약:**
	
	- **(답): 참조**
