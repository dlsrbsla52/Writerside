# 23-10) Staging 서버 구축

AWS의 비용 문제로 DEV 환경에서 모든 테스트를 진행하기 어려운 부분이 있었습니다.

예를 들어 S3에 많은 파일이 존재하고, 이 파일에 대한 메타 데이터를 운영 DB가 가지고 있기 때문에 문항의 메타 데이터가 연동되고 S3의 파일이 존재하지 않는다면 예정된 작업을 수행할 수 없었습니다.

이런 개발상의 이슈로 개발자들은 DEV 서버에서 테스트가 필요할 때면 .yml파일을 수정해서 Spring이 운영 DB, 운영 S3를 바라보게 하고 테스트를 진행 했었어야만 했습니다.

이러한 작업들이 반복적으로 일어났고 .yml파일을 수정해서 운영과 비슷한 환경에서 개발자들이 테스트를 하고 있으면 통합 QA진행 일정이 딜레이 되거나 잘못된 파일들로 인해 운영상 이슈가 될 여지가 충분히 많다고 판단 했었습니다.

이를 해결하기 위해 실제 운영과 같은 환경으로 서버의 용량은 작게 구축하여 통합 QA와 배포 등의 문제에서 자유로워질 수 있었습니다.

웹 서버는 Nginx, WAS는 Spring boot의 내장 톰캣으로 구축하여 배포를 진행 하였고

jenkins와 GIT을 통해 CI/CD를 구축하여 자동 배포 및 형상 관리를 유지할 수 있었습니다.
